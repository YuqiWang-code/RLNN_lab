# 数据读取与图转换性能

当前训练使用预转换 CPU 张量、8 个 DataLoader worker、pin_memory 和 persistent_workers。缓存保留原始图的节点数、边顺序与文件索引顺序，训练时只重建所需 Data 字段，不再逐轮执行 NetworkX 转换。

GPU 1，13 图合批，每图 1000 状态；每项使用相同 104 图运行两个 epoch，报告第二轮训练全过程。计时包括读取、图组装、CPU→GPU 传输、轨迹采样、前向、反向与更新，排除验证及 checkpoint 保存。

| 数据格式 | workers | 104 图训练秒数 | 输入等待秒数 | 训练阶段 GPU 平均计算利用率 |
| --- | --- | --- | --- | --- |
| raw | 0 | 32.620 | 28.427 | 6.5% |
| raw | 4 | 11.239 | 7.008 | 21.7% |
| tensor | 0 | 4.405 | 0.187 | 65.2% |
| tensor | 4 | 4.564 | 0.353 | 65.0% |
| tensor | 8 | 4.381 | 0.258 | 70.6% |

缓存加 8 worker 相对原始读取加 0 worker，训练阶段耗时降低约 7.45 倍。主要收益来自消除重复图转换；缓存下 0/4/8 worker 的速度接近，采用 8 worker 为批次预取留出吞吐余量。该短测不直接代表包含验证的完整 epoch 倍率。

原始测量位于 `outputs/v000_rlnn_baseline/loader_benchmark_*/benchmark.json`，包含输入等待、设备计算和逐批次记录。缓存信息见[缓存清单](../outputs/v000_rlnn_baseline/data/cache_summary.json)。数值以 benchmark/ 前缀进入实验工作簿，不作为正式测试成绩。

完整 1000 图续训验证中，训练阶段已测得 39–40 秒/轮；原运行最近一轮为 4 分 57 秒。加上验证约 85 秒/轮，模型训练阶段的约 7.4 倍提速已在完整训练集复核。

## 缓存准备

服务器项目根目录执行 `bash train_scripts/legacy/v000_rlnn_baseline/prepare_cache.sh`。原始数据保留在 `models/data/MIS/`；缓存位于 `models/data/MIS_tensors/`，张量文件不下载、不入 Git。训练、验证和测试分别使用独立目录，manifest 保留原始文件顺序。

## 续训协议

本次从旧运行第 22 轮最佳权重继续到总第 50 轮。旧运行实际完成的 24 轮日志保留，当前模型分支继承其中 1–22 轮。旧 checkpoint 缺少 Adam 和随机数状态，二者重置；run.json 记录权重来源及重置标识，工作簿继承行使用原配置和日志来源。

新代码每轮保存模型、最佳权重、Adam、主进程随机状态、epoch、累计更新数与历史记录至 latest_training.pt。模型/优化器状态恢复、历史合并和更新计数已通过一次真实续训检查；重建 worker 后的数据加载随机序列不承诺逐位一致。

DataLoader 参数依据：[PyTorch 2.9 文档](https://docs.pytorch.org/docs/2.9/data.html)。
