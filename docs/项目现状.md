# 项目现状

## 代码与实验

当前实验版本为 `v001_tsp100`，初始代码归档为 `v000_baseline`。代码包含 TSP、CVRP、MIS 的一致性训练和解码流程。`models/train.py` 为统一入口，`diffusion/pl_*_model.py` 对接 Lightning，`consistency/` 实现损失与推理，`co_datasets/` 读取数据，`models/` 内的 GNN 和 Transformer 提供骨干网络。

TSP、MIS 默认使用 `gnn_encoder.py`；CVRP 使用 `gnn_cvrp_encoder.py`。`block_gnn_encoder.py` 和 `cvrp_gnn_encoder.py` 为额外实现，当前训练入口未引用。TSP 合并代码通过 Cython 扩展执行，CVRP 本地搜索通过 C++ 共享库执行。

启动脚本版本与输出版本对应。所有启动脚本在 `models/` 工作目录执行，默认单卡，追加参数可覆盖默认实验设置。TSP500、TSP1000 的启动配置使用正数 `rewrite_steps`。`test_misrb_large.sh` 执行大规模 RB 图测试。

TSP100 已完成 10,000 个 LKH 标注实例上的一轮训练，并测试全部 1,280 个固定实例，扩展后平均 gap 为 1.0085%。训练、验证和测试数值记录在 `docs/实验结果.xlsx`，汇总见 [TSP100 基线](TSP100基线.md)。专用环境、数据生成方式和复现命令见 `train_scripts/v001_tsp100/README.md`。

## 已知问题与待准备项

- 其他规模 TSP、CVRP 和 MIS 的训练数据尚未准备。现有数据及实例数见 [数据集](数据集.md)。CVRP100 启动配置的验证与测试指向同一文件，作正式对比实验前需要单独确定验证划分。
- RTX 5090 使用 `models/environment-5090.yml`，Python 3.10.19 / PyTorch 2.9.1+cu130 / Lightning 1.9.5 / NumPy 1.26.4。Cython 和 CVRP 本地搜索已编译，编译产物保留在服务器，源码通过 Git 管理。
- TSP 的旧 `merge_tours()` 路径调用了未导入的 `merge_cython`；当前一致性推理使用 `merge_sub_tours()`。使用旧合并路径前需要修正导入及参数签名。
- `merge_sub_tours()` 在节点数大于 1000 且 `parallel_sampling > 1` 时，进程池直接返回 Cython memoryview，缺少串行分支中的 NumPy 转换；该配置需验证进程间返回值的可序列化性。
- TSP 当前只构建一组初始解，`sequential_sampling > 1` 不会增加候选组数。本版使用 `sequential_sampling=1`。
- CVRP 稀疏数据分支返回的 batch 结构与当前一致性流程所解包的稠密结构不同，且 `cvrp_utils.merge_tours()` 未实现稀疏分支。当前 CVRP 启动脚本使用稠密图。
- GNN 的稠密路径未实现 `use_activation_checkpoint`。当前启用该参数的 TSP1000 和 MIS 启动脚本使用稀疏路径。
- 三个任务的 `build_solution()` 通过 `rewrite_steps` 次循环更新最优解；设为 0 会留下无穷目标值，启动参数应使用正数。
- 验证数据加载器直接取 `range(validation_examples)`；参数大于实际验证集实例数时会越界。补充验证集后应与实例数对齐。
- MIS 缺少节点标签和外部标签时以全零标签加载；推理 gap 的参考目标为标签和，零标签会使 gap 除以零。MIS 评测需要完整有效的参考标签。
- `CVRPModel` 总是构建 CVRP GNN，`--model_type transformer` 不会选择 CVRP Transformer。当前 Transformer 路径用于稠密 TSP。
- 服务器 `/home` 使用率约 96%，完整训练数据和多次检查点保存需要留意剩余容量。

## 后续实验顺序

在固定的 TSP100 数据划分和推理预算上增加训练轮数，再比较 GNN、Transformer 与不同扩展策略。其他任务分别准备训练集、验证集及有效标签后建立基线。
