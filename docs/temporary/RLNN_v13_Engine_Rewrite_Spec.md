## §2 步数预算重定义

1. **三种合法比较**：同墙钟（SOTA 主口径，必须含 load+decode+PAVE）、同步数（机制/消融口径）、同质量（交叉点口径，报「达到 20.069 所需秒数」）。论文主表只能用同墙钟；机制图用同步数；**不许在两种口径间挑对自己有利的那个**。
2. 新引擎 1 s 步数记 `S_new`（**实测，不许预测**）。`S_new ≥ 1600` 时，1 s 行必须同时打印步数；旧 810 步结果降级为「同步数对照」，不得再叫「1 s 结果」。
3. **KaMIS 20.1020 @ 3.046 s**（墙钟地板 1.87 s、`--time_limit=1` 时 1000 图只 99 图返回、那 99 图 19.8384）：只能主张「1 s 内我们交解、它交不出」或「≥3 s 同墙钟比」。
4. **RLSA** 20.0730 @ 0.6505 s、20.0930 @ 1.2898 s、1 s 插值 20.084：同墙钟直接比；**禁止**拿它的 0.65 s 结果对我们的 1 s。跨预算互比一律禁止（FLD 38 s 的 20.02 不得与 1 s 比）。
5. **步数是随机量**：deadline 驱动下同一 0.2 s run 实测 **119.3–145.0 步（三 seed，抖动 22%）**。任何短档对照必须**同时报步数**，并对照「步数-质量」曲线后再比分数；直接比 `mean_search` 会把机器抖动当算法差异。
6. **短时域固定开销单列**：sync/sample/archive/decode/load 合计 ≈**0.35 ms/步等效、占 0.2 s 预算 28%**（P0 实测：有效步成本 1.23 ms = 0.877 前向 + 0.35 固定）。它是 systems 可优化项，但**改它必须证明 quality 不变或变好**，否则只能算「同质量换速度」。
7. **定标与结论分两层（captain 2026-11-18 追加）**：固定步数曲线（130/200/280/350/450，seed 1017）**只用于预测**「280 步值多少分」；**结论必须由重写后的「同 0.2 s deadline × 三 seed × 报步数」那一格确认**——固定步数臂与 deadline 臂的固定开销分摊不同（0.35/1.23），拿前者绝对值替后者等于把那 28% 当常数抹掉。只有 deadline 臂三 seed 步数落在 **270–290** 且质量 **≥19.98**，才可写「0.2 s 打平/小胜」；否则走 §4 降级支。

## §4 收益轴重排（本任务最重要的一条）

- **现行 1 s（K=200、fp16+dense）**：810 步 @0.867 ms → **20.0690**。810 → 1782 步按曲线只值 **+0.02–0.03**（397→808 仅 +0.0265；1000→3000 步仅 +0.058，`RLNN_v12_R2_E1_Variance.md:35`）⇒ **20.09–20.10**，仍在 KaMIS 20.1020 之后。
- **现行 0.2 s（K=20、fp32+CSR）**：413.7 步 → 19.8410 @0.188 s（`RLNN_v8_Amortised_Capture.md:67`）；同档 RLSA **19.9620 @0.201 s** ⇒ 落后 0.12——但这是**不同 K 的对比，属口径事故**，不能进论文。
- **P0 实测（0.2 s × K=200 × fp16+dense，三 seed，t24 前唯一一格）**：**130.1 步（119.3–145.0）**、search **19.886** / final 19.908 ⇒ 对 RLSA **落后 0.076**；有效步成本 **1.23 ms/步 = 0.877 前向 + 0.35 固定（28% 预算）**。⇒ 「K=200 在 0.2 s 能装 230 步」**作废**。

**条件式收益陈述（不再给点估计）**：若重写达 **1.9×**，0.2 s 约 **270–290 步**（不是 508）。该格值多少分取决于「步数-质量」曲线，t24 正在实测定标（130 / 200 / 280 / 350 / 450 步，seed 1017）：
- **280 步 ≥ 19.98** ⇒ 0.2 s 与 RLSA 打平/小胜，**值得做**（收益轴仍在小预算档）；
- **280 步 ≈ 19.94** ⇒ 1.9× 也不够，SOTA 陈述收回到「**1 s 内 KaMIS 交不出解**」，**不要押两天**。

## §4.1 0.384 与 0.867 的口径核算（captain 追问，2026-11-18）

**口径**：两条臂的 ms/步 都用 `search_time_s / steps`（0.2 s 臂 = 0.1585 s / 413.7 = 0.384；A0 同式、含每块 decode + `sync_each_block`）。0.2 s 臂是 **K=20、fp32+CSR、`decode_every=1`、整集摊一次 `capture_s=0.817`**，且 **不含** load 5.9 ms、prelude 11.4 ms、PAVE 预留 40 ms（`padded_ref0.csv` 逐列均值 + `padded_ref0.json`）；A0 是 **K=200、fp16+dense**。
结论（5 行）：
1. **不可直接换算**：K 差 10×，单步成本 ∝ K —— K=20 的 1 s 臂 0.329 ms/步，K=200 fp16+dense 0.867 ms/步（2.6×）；「短时域更便宜」只解释 0.329→0.384 的 **+17%**，其余全是 K 与 dtype/邻接。
2. 故「413.7 × 2.2 ≈ 910 步」是 **K=20 的步数预算**，不能拿 K=200 的 808 步曲线（20.0690）估质量 —— §4 的「20.06」是跨 K 混用，**作废**。
3. 同 K 换算：保持 K=20 ⇒ 910 步在 K=20 曲线上（414→19.8410、1310→19.9450）只值 **≈19.92**，仍落后 RLSA 19.9620 约 **0.04**。
4. 正确走法 = 0.2 s 换 K=200：今日 0.2 s 在 0.867 ms/步下只 230 步（≈20.02，参照 244 步 → 20.0235）；2.2× 后 0.394 ms/步 ⇒ **≈508 步 ⇒ ≈20.05**，对 RLSA **+0.09** ⇒ 换轴结论仍成立，但必须实测，且基线不能用 K=20 的 19.8410。
5. **前置门（t21 G0）**：提速必须在「目标档同一 K、同一 dtype/邻接、同一 decode 节奏」下报 ms/步与实际步数；**禁止跨 K、跨 1 s/0.2 s 外推**。
6. **P0 复核（2026-11-18，captain 实测）**：0.2 s × K=200 × fp16+dense 只有 **130.1 步**（三 seed 119.3–145.0）⇒ 本节的「230 步」假设**作废**，1.9× 后也只到 **270–290 步**（非 508）。另：我引的 244 步 / 20.0235 出处是 **1 s、K=200、fp32+CSR、每块 decode**（`v10_paper_snapshot_A.txt:117`；`RLNN_v9_SOTA_Hunt.md` §3 四档 24/60/101/244 步一致），**只能作步数锚点**，含 dtype 偏差 ±0.007 ⇒ 区间 **[20.00, 20.04]**；且本地无任何 K=200 且 steps<400 的 CSV（15 个短步数 run 全是 K=20 或 ER 图），**P0 是全库第一次测该格，无交叉验证，只能靠三 seed 复核**。

## §5 kill criteria（任一命中即退回旧引擎并写负结果）

1. 1000 图 `search_size` 均值漂移 **>0.01**；
2. 图级 `|Δ| ≥ 2` 的图 **>1%**，或任一图 `|Δ| ≥ 3`；
3. 实测提速后 **1 s 档收益 < +0.010**，且 **0.2 s 档收益 < +0.040**（两条都不满足 ⇒ 这轮 1–2 天不值，按版本 A 收口）；
4. 为拿速度牺牲可审计性（无逐图 CSV、无 dtype/steps 列、三 seed 不全）⇒ 即使数字好看也不作部署口径。
