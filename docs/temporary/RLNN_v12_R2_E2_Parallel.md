| 1 | 200 | **0.8133** (0.807/0.814) | 0.147 | 1.000 | 810 |
| 2 | 400 | **1.9436** (1.943/1.946) | 0.285 | **2.389** | 330 |
| 3 | 600 | **3.5612** (3.560/3.562) | 0.422 | **4.379** | 180 |
| 4 | 800 | **4.9955** (4.994/4.997) | 0.560 | **6.142** | — |

分项：forward 0.877 / 1.989 / 3.607 / 5.030，sample(=forward+rand+where) 0.894 / 2.010 / 3.626 / 5.047，
decode(1 臂) 0.274 / 0.249 / 0.245 / 0.243，而 **energy_csr 恒 0.034、energy_dense 恒 0.026（N 无关）**。
读法：单步成本 ≈ **策略前向 GEMM**（0.877 ms @ 264×264×200 ≈ 14M MACs ≈ 32 GFLOP/s，效率低但在关键路径上）；
CSR spmm 只占 4% ⇒ 引擎注释里「CSR ~1 GFLOP/s 是瓶颈」的猜测**不成立**；`sample` 仅比 forward 多 0.02 ms。
前向随 K 近线性到**超线性**（1→2×: 2.3×；1→4×: 5.7×）⇒ batch 复制**无可摊销的空闲容量**，
「launch-bound ⇒ c 可能 1.3–2.0」被证伪；显存极小（N=4 仅 0.56 GiB）⇒ 不是 OOM 限制。

## (c) 每臂实际步数与 deadline

`floor(810/c)//10*10` = 810 / 330 / 180 步；实耗 0.662 / 0.643 / 0.645 s（1.0 s 预算、0.2 s 留给 PAVE），
**三者均为步数封顶、未触发 deadline**（`max_blocks` 固定、`run(inf, ...)`）；平均每图墙钟 0.701 s。
## (d) 判决

**关闭**：等墙钟下 2 臂「打平偏负」（Δ −0.020，CI 跨 0，188/200 图并列），3 臂显著更差（CI 不含 0）。
回本需 c ≤ 1.60（宽松 1.79），实测 c(2)=**2.389**、c(3)=**4.379**，超出 49% / 120%，靠调步数救不回；
不跑三 seed、不进 1000 图决赛（方差路线在硬件上不成立，属结论边界而非参数问题）。
给 E3 的可迁移事实：单步 95% 是前向 GEMM，每 block 一次 `torch.cuda.synchronize` ≈ 0.4 ms/8.2 ms ≈ 5% 上界，
「减少 host 同步」最多省这 5%；要么改前向本身（宽度/精度/图内复用），要么放弃在 1 s 内塞多臂。
