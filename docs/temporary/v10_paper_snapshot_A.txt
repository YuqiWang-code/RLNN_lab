1. 一句话主张（写论文就用这三段）
------------------------------------------------------------------
①  把冻结的神经搜索循环做成 CUDA 图块，并**一次捕获服务整个数据集**（padded 引擎），
    每图预热从 93.5 ms 降到约 6 ms；再把「每块回读解码」换成「只解码 top-k 档案」、
    邻接从稀疏 CSR 换成 dense、精度降到 fp16，1 秒内的步数从 244 涨到 808，
    作者 1000 图 1.0 秒档 **20.0685**（同钟 K=20 基线 19.9830）。
    在 RLNN 的每图时钟（0.197 s）上，0.2 秒档 **19.8410** 让 SIZE 与 TIME 两轴**同时**超过 RLNN 19.52。

②  后处理平台 PAVE 的增益是**输入解次优程度的函数**，不是常数：
    贪心起点 +0.710，我们 0.5 s 的弱搜索 +0.222，已收敛的解 +0.000。
    因此「捕获」与「平台」是替代关系而不是相加关系——这是原计划里写错的一条，
    本版论文把它作为一个可迁移的诊断结论呈现，而不是作为一个 additive 贡献。

③  十三条方法线（v1–v10）的负结果 + 三个诊断探针，构成方法论部分：
    同钟对照、图级配对自助 CI、逐位闸门、预注册判读表、时钟 bug 的可复现暴露、
    以及「负结果也要有机制解释」。核心机制句：
    **RB[200–300] 上 1 秒内的解已是「1-flip + (2,1)-swap + 破坏-修复」三重邻域的不动点，
      策略在 50 步内进入吸引子，剩下的步数只是抖动。**

4. 摊薄捕获与时钟修正（这一版论文里唯一真正赢的机制）
------------------------------------------------------------------
4.1 问题
逐图捕获要整块录一次 CUDA graph，约 93.5 ms；0.2 s 时钟里占 47%，
0.1 s 以下一步都走不了（实测 0 步，解 17.67/17.99）。

4.2 做法（models/mis_v8_pad.py，class PaddedSearch）
  · 固定 CSR 布局：crow = arange(0, rows*cap+1, cap) 恒定，cap = 数据集最大出度+1；
    只有 col/raw/norm/bias 这些**缓冲区内容**每图重写（copy_），形状不变 → 图可复用。
  · 单一持久 torch.Generator（register_generator_state 进图），每图 manual_seed 重置。
  · 每个图 load 只写缓冲（约 n_max×cap 个元素），实测 6 ms。
  · 解码用捕获版 A.3（chunk=4），或 `--decode_top k` 只解 top-k 能量列。
  · 过冲安全：收敛后 where(gain>0, 1-x, x) 不动状态，多跑是 no-op。

  闸门（models/check_padded_capture.py）：
  · capture replay vs padded eager：**逐位相等**（60 步状态/档案/解码 bitset），硬断言。
  · padded vs 未 padded：只报 drifted_nodes 与 |Δsize| ≤ 1（实测 drifted 66–178，
    解大小全部一致；spmm 差 8.94e-08、logits 差 1.72e-05）。

  必须单进程：4 分片并发时 0.05 s 档只走 0–5 步、1.0 s 只到 650–900 步。

4.3 时钟 bug（2026-11-16 定位并修复）
  症状：K=200 的 `--decode_every 1000` 臂在 1 s 预算下报「3861 步、SIZE 20.450」，
        而同配置 `decode_every 1` 只有 244 步、20.0235。
  根因：`run()` 里 `started = perf_counter(); graph_exec.replay(); steps += chunk`
        —— **replay 只入队不阻塞**，块耗时只有几十微秒，
        `perf_counter() + block_time >= deadline` 永远不成立 → 循环跑到 CUDA 队列深度上限。
  修复：`run(..., sync_each_block=True)`，每块 replay 后 `torch.cuda.synchronize()`。

  预算    修复前 实际耗时   修复前 块/步      修复后 实际耗时   修复后 块/步
  0.05 s  9.670 s          343 / 3430       0.029 s          1 / 10
  0.20 s  9.694 s          348 / 3480       0.177 s          6 / 60
  1.00 s  10.513 s         376 / 3760       0.978 s         33 / 330

  → K=200 真实单步 2.96 ms，1 秒只能 330 步；「3861 步」是约 10 秒的产物，全部作废。
    `decode_every=1` 的旧数据不受影响（每块 decode 会隐式同步）。

4.4 单步成本模型与三个加速杠杆
  单步 ≈ 2.96 ms（K=200、5×128、fp32）。主项是 5 层 Linear(128,128) 作用在 (264×200) 行上：
  865 MMAC/层、合计 4.3 GMAC ≈ 8.6 GFLOP；CSR spmm（27k nnz × 200 ≈ 5.4 MMAC）只占 ~0.1 ms。
  → **成本 ∝ K × hidden²，与层数线性**。

  K=200、1 图、1.0 s 的四种配置：
    fp32 + CSR    260 步   3708 µs/步
    fp32 + dense  310 步   3142 µs/步   （GCNConv 对 strided 邻接走 torch.matmul）
    fp16 + CSR    310 步   3239 µs/步
    fp16 + dense  470 步   2084 µs/步   ← 最终配置
  正确性：logit max |diff| = 1.597e-05（fp32 dense vs CSR）；fp16 为 6.3e-02（累加顺序舍入）。

  另一项是「每块解码全部粒子」→ 改成 `--decode_top k` 只解 top-k 能量的列：
  单图 K=200 实测 captured decode_best 0.011 s、eager decode_top 1/2/4/8 = 0.150/0.009/0.007/0.007 s。
  注意：`decode_every` 本身**压不掉**开销——`run()` 是「到 deadline 为止尽量多跑块」，
  跳过解码的块更快，单位时间的解码次数守恒（decode_every=3 实测 20.0030 < 20.0235）。

5. 平台 PAVE：增益是输入次优程度的函数（诊断性结论）
------------------------------------------------------------------
机制：PAVE = repair（size+1 交换）+ extend + 学习排序器（PAVEV3）选择候选，
      预算内反复 outer_rounds 轮；它只能修「还没到局部最优」的解。

实验（100 图，同一套 PAVE 超参，只换输入）：

  输入                     输入 SIZE   PAVE 后   增益 [95% CI]              胜/平/负
  最小度贪心               18.3800     19.0900   +0.7100 [+0.5600,+0.8700]  53/47/0
  我们 0.5 s 捕获搜索      19.8750     19.8750   +0.0000                    0/100/0
  KaMIS 0.1 s              20.0500     20.0500   +0.0000   [0,0]            0/100/0
  （KaMIS 六臂：extend/pave/rule/random/long 全部 +0.0000，三个 PAVE 臂
     exchanges 均值 0.00、100/100 图零次交换，extend_gain 0.0 —— 已是极大集）

排序器本身的价值（只在弱构造器启动时可见）：
  学习 19.0900 vs 规则 18.9300：+0.1600 [+0.0800,+0.2500] 15/84/1
  学习 vs 随机 18.9500：        +0.1400 [+0.0700,+0.2200] 14/85/1
  规则 vs 随机：                −0.0200 [−0.0800,+0.0300] 2/95/3

结论：**PAVE 不是 solver-agnostic**。它是「把未收敛的解修到局部最优」的算子，
      增益随输入收敛程度单调下降（0.710 → 0.222 → 0.000）。
      论文里不能写成「接在任何求解器输出上都能 +」。

    部署（1000 图，摊薄捕获 + 冻结 PAVE，seed 1017）：
          时钟   frozen    scale     norm     scale−f  norm−f
          0.05   19.4040   18.6960   18.5175  −0.7080  −0.8865
          0.10   19.6890   18.9555   19.2435  −0.7335  −0.4455
          0.20   19.8410   19.1110   19.5980  −0.7300  −0.2430
          0.50   19.9450   19.1835   19.8200  −0.7615  −0.1250
          1.00   19.9830   19.2070   19.9115  −0.7760  −0.0715
    scale 五档恒定 −0.71~−0.78 → 死于表达力；norm 差距收窄但等步数对照
    （1347 步 19.9115 vs 冻结 1310 步 19.9450）仍低 0.034 → 死于吞吐（每层多一组 kernel，2.1×）。

6.8 v10 换移动集（否）
    ① 精确重组：80 个去重档案解两两重组（a∪b 内的全局最优），两图 search 22/19 → 22/19，
       **增益恰好 0**，而重组只要 17–75 ms（算得起，是算了没用）。
       独立复现：RLSA 自己的 200 粒子种群 oracle +0.000（best 19.85 / chain 19.90 / oracle 19.85）。
    ② 受禁破坏-修复（半径 1/2/3 × 周期 2/10/40 × 档案回退，20 图，1.0 s，基线 20.4500）：
       周期 2 不回退 −0.275（0 胜/29 平/11 负，只是少 121 步的钱）；
       周期 10 下三档半径与基线**逐位相同**。
    ③ 缩减重启：RB[200–300] 度 ≤3 顶点占比全 0%，四种规则迭代到不动点还剩 88.1% 顶点。
    机制：**不动点会被修复回来**（tabu 释放后策略把同一个球里的点又选回去）。
    结论：移动集不是约束，**修复算子才是**。见 RLNN_v10_Move_Set.md。

          臂                    现任解        轮数    Δ>0   正样本率   平均 Δ
          标准（best-of-4）      19.79        20800    50    0.24%     −0.29
          收敛（best-of-64）     19.97         6720     4    0.06%     −0.43
    Δ 直方图（标准）：{−3:18, −2:795, −1:4463, 0:15474, +1:50}；**从未出现 +2**；
    74% 轮次 Δ=0；正样本率与图规模无关（16→0.17%、20→0.48%、23→0%）。
    门是 1%（需 >200 正样本）→ 不过，关线。措辞：破坏-修复不是严格恒等变换，
    是「几乎闭合、带 0.2% 漏」的算子。

6.10 冲 SOTA 的其余杠杆（全部为负）
    · 组合（portfolio）：严格 ≤1 s 的 max(我们, RLSA) 上限 20.0550（0.5+0.33 s），
      1.79 s 才到 20.0970 → 限时内上限≈20.08，不是杠杆。
    · 神经引导 RLSA（delta += w·logit，w∈{0,0.05,0.1,0.2}，100 图，num_t=1000）：
      19.9800 / 19.9200 / 19.8700 / 19.7600 → w=0 最好，加先验单调变差且慢 39%。
    · 宽种群 K 扫描（固定 700 步）：K=20 19.65 / 50 19.80 / 200 19.90 / 800 19.90 → 饱和。
      K=200 部署的等钟对照：0.1 s 18.9035 / 0.2 s 19.5225 / 0.5 s 19.9160 / 1.0 s 20.0235。
    · decode_every=3：20.0030 < 20.0235（每秒解码次数守恒）。
    · 3 层砍深：步数 ×2.1（1729）、SIZE 20.0610 < 808 步的 20.0685。
    · 翻转率探针（3 图）：每步只翻 1.70%/2.19%/2.18%（4–5 点），
      密度第 50 步就到 0.091 然后 200 步不变 → **策略 50 步内进入吸引子**，
      这就是「步数每翻倍只值 +0.01」的机制，也统一解释温度/交换/重组/PAVE 为什么全无效。

7. 明确不主张的边界（写论文时必须写进 limitations）
------------------------------------------------------------------
· 不主张 SIZE 超过 KaMIS（20.1020）或 RLSA（1 秒插值 ≈20.084）。
  1.0 s 档我们 20.0685：比 KaMIS 低 0.033，比 RLSA 低 0.016。
· 不主张 TIME 优势：1 s/图 对 RLNN 的 0.197 s/图 慢 5.1 倍、对 RLSA 的 0.208 s/图 慢 4.8 倍。
  只有 0.2 s 档（19.8410）在 RLNN 的等钟上成立。
· 不主张两个组件可相加：捕获与平台是替代关系（§5）。
· 不主张跨图族/跨规模泛化：ER、BA、n≈1000 全部退化（§6.6）。
· 主表只有搜索种子 1017（三种子 CI 待补）；单机单卡。
· KaMIS 的 TIME 含进程启动 + 图写盘约 1.87 s/图，所以「1 秒以下只有我们能交解」
  是框架地板差异，不能作为卖点。
· 「时钟修正后步数 ×16」这类数字不能单独引用：它是 bug 的暴露，不是方法的贡献。
