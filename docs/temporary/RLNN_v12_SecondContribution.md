# v12 第二创新点定型备忘

2026-11-17 · literature · 供用户裁。规则：每个数都指到盘上的 CSV/report/文档行，**未跑出的一律标「待补」**。

## 0. 答案

**第二创新点 = 「闭包判据」（closure criterion）：修复类后处理的增益由输入的闭包缺口 C 决定（不是选择器的表达力），1 s 档 C≡0 ⇒ 增益上界严格为 0；C 可被 ≤5 ms 前向预测，用它决定要不要调修复。**
形态：「闭包判据」为主贡献，卖点是**增益的可判定上界 + 部署门控**；诊断 I/II/III 是它的支撑小节，P1（增益可预测性）作为第四节并入。**P1 不单列**——单列会被「你在给一个零增益组件做门控」打死。

## 1. 排序

| # | 候选 | 数据成熟度 | 最大风险 |
|---|---|---|---|
| 1 | **「闭包判据」**（closure criterion；三机制 + 严格上界） | 高：216 点阶梯、648 格精确移动、四条证伪线全在盘 | 36 图 → 1000 图外推；C 用自有算子定义（自指） |

## 2. 候选 1｜闭包判据（closure criterion，推荐）

- **一句话主张**：平台饱和不是「搜得不够」，而是解已落在三重邻域（1-flip、k≤4 交换、破坏-修复）的共同闭包内；闭包缺口 C 是后处理增益的严格上界，1 s 档 C≡0 ⇒ **后处理在 1 s 档的期望增益上界为 0**。
- **需要哪些表与图**：T4 六档阶梯（greedy→1.0 s，G/C 由 +1.000/+1.056 降到 0/0）；T5 拟合双口径（档均值 R²=0.989 vs 逐点 0.272，ρ\*=0.0901 为外推）；T6 逐图 C 分布（0.1 s 12/36 图 C>0、0.2 s 1/36、1.0 s 0/36）；T3 三重不动点；T7 梯度三臂；F2 正样本直方图、F3 C–ρ 散点（双拟合 + ρ\* 竖线）。
- **现有数据够不够**：**基本够**。`train_scripts/v11/validation/data/ladder.csv` 有 216 行 per-graph C/G，`results/matlab_M2/M3/M4*.txt` 齐全，边表 `data/edges/` 36 个。缺 1000 图复测：36 图子集 1 s 均值 20.4167（python 侧；MATLAB 755 步复算 20.472）比 1000 图 20.0685 容易约 +0.35（`RLNN_v11_MATLAB_Validation.md:61`）。
- **最大审稿风险**：C 用我们自己的 `platform_search(deadline=∞)` 定义 ⇒「用方法定义自己的标签」。唯一挡法是在外部输入上 C 同样为 0（KaMIS 0.1 s 100 图：0/100/0、+0.0000、CI [+0.0000,+0.0000]，`RLNN_v8_PAVE_External_Results.md:29-88`；`README.md:58` 同口径）。次要风险：「C≡0 只因为你搜得不够」→ 用阶梯回答，0.2 s 已 35/36 图 C=0，不是只有 1 s。
- **kill criteria**：1000 图上 1 s 档 C>0 的图 >2% → 上界不成立，降级为 36 图观察。

## 3. 候选 2｜P1 增益可预测性（并入候选 1）

- **一句话主张**：一次 ≤5 ms 前向（O(m) 扫边 + 24 维 stats MLP）在跑 1 s 之前估 C，C<τ 就不调 PAVE——把「+0.004 的末端后处理」改写成「该不该调修复」的部署规则。
- **需要哪些表与图**：T9 门控表（图数、R²、放行率、省下的时钟、质量差）、F4 τ 扫描曲线；正文需给出 5 ms 预算的分解（构图统计 ≪ 5 ms，MLP 可忽略）。
- **现有数据够不够**：**不够**。标签 C 只有 36 图；特征器现成（`models/mis_v3_value.py:8 STATS_DIM = 24`，`graph.stats_features(selected, actions, remaining=…)`），边表也只有这 36 图。需 1000 图 × 1–2 档的 (stats, C) 表。
- **最大审稿风险**：图级 R² 天花板 0.272（C 是整数、多数为 0，离散化噪声大）；且 1 s 档 36/36 图 C=0 ⇒ 门控在该档恒答「不跑」、零信息，非平凡判断只出现在 0.1 s（12/36）与 0.2 s（1/36）。省下的钟值多少钱也没证：700 步后每翻倍仅 +0.01（`README.md:57`）。
- **kill criteria**：1000 图门控 R²<0.1，或「放行图」与「拦截图」的实测增益无差（AUC<0.6）。

## 4. 候选 3｜闭包剖面协议（备选，只进 appendix）

- **一句话主张**：任何 anytime 求解器的每个输出都可标注「离自身闭包多远」，得到与预算无关的完备性指标；给 4–6 个 solver × 2 档的剖面表。
- **需要哪些表与图**：T11 剖面表（solver × 预算 → C 分布）、F5 剖面图（C 随预算衰减）。
- **现有数据够不够**：**部分**。KaMIS 0.1 s（100 图 C≡0）、RLSA 解、我们 6 档；其余 solver 需补跑 C。
- **最大审稿风险**：被读成 benchmark 附录；C 依赖自有算子，需算子无关版本（统一 LNS 核）才立得住。
- **kill criteria**：任一 solver 上 C 的分布与已知 PAVE 增益不同序（Spearman<0.6）。

## 5. 推荐与理由

1. 只有「闭包判据」能把「v1–v10 十三条线全负」变成**可解释的定律**，且不烧 GPU、数据已在盘 → 风险最低。
2. P1 作为「闭包判据」的推论（上界的部署形式）反而加分；单独做主贡献则暴露「门控零增益组件」的尴尬。
3. 候选 3 补跑最贵（每 solver × 100 图 × C），留 appendix 或 future work。
4. 打包后第二段话已成立：**「PAVE 不是没用，是被闭包吃掉了；我们给出判据，并证明它在 1 s 档的期望增益恒为 0。」**

## 7. 待补清单（按性价比）

1. **1 s 档 1000 图 C 分布 —— 立命之本**：36 图子集比 1000 图容易约 +0.35（`RLNN_v11_MATLAB_Validation.md:61`），故 36/36 图 C≡0 **不能直接外推到 1000 图**。这是 t7(B) 的测点，它决定写哪篇：若 1000 图上 1 s 档 C>0 的图 >2%，「**严格**上界 0」降级为「**经验**上界」，全文改口。CPU，每图一次 `platform_search(deadline=∞)`。
2. 0.1 / 0.2 s 档 1000 图 C（B 的标签，同时是「非平凡区间」证据）。
3. 1000 图 × 24 维 stats → 小 MLP（≤2 h）。
4. 门控部署臂：0.2 s 档 {纯搜索, PAVE-on, gate-on} × 1000 图 × 3 种子（≈1.5 GPU·h）。
5. 外部 C 剖面：KaMIS 0.1 s / RLSA，各 100 图。
6. **（可选，≤0.3 GPU·h，待用户确认后派）S3 补测**：从**部署解**（20.0 收敛解）出发的动作级 FIFO tabu 逃逸测试，200 图 × 8 轮 × 0.2 s —— 把 S3 从「论证」变「实测」；现有唯一实测干预 C4 的起点是 17.1 贪心解，不能代表部署解（`RLNN_v11_Review.md:67-77` P4）。
