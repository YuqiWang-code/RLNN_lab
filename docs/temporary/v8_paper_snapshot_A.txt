1. 一句话主张（A 版，写论文就用这三段）
------------------------------------------------------------------
①  把冻结的神经搜索循环做成 CUDA 图块，并**一次捕获服务整个数据集**（padded 引擎），
    每图预热从 93.5 ms 降到约 6 ms，同钟步数 ×6，0.2 s/图的解从 19.397 抬到 19.841；
    在论文 RLNN 的每图时钟（0.197 s）上，SIZE 与 TIME 两轴**同时**超过 RLNN 19.52。

②  后处理平台 PAVE 的增益是**输入解次优程度的函数**，不是常数：
    贪心起点 +0.710，我们 0.5 s 的弱搜索 +0.222，已收敛的解 +0.000。
    因此「捕获」与「平台」是替代关系而不是相加关系——这是原计划里写错的一条，
    本版论文把它作为一个可迁移的诊断结论呈现，而不是作为一个 additive 贡献。

③  九条方法线 + 重训 + 重组 + 交换/踢动调度的负结果，构成方法论部分：
    同钟对照、图级配对自助 CI、逐位闸门、预注册判读表、以及「负结果也要有机制解释」。

4. 摊薄捕获：机制（这是论文里最"工程"的一节，也是唯一真正赢的机制）
------------------------------------------------------------------
问题：逐图捕获要整块录一次 CUDA graph，约 93.5 ms；0.2 s 时钟里占 47%，
      0.1 s 以下一步都走不了（实测 0 步，解 17.67/17.99）。

做法（models/mis_v8_pad.py，class PaddedSearch）：
  · 固定 CSR 布局：crow = arange(0, rows*cap+1, cap) 恒定，cap = 数据集最大出度+1；
    只有 col/raw/norm/bias 这些**缓冲区内容**每图重写（copy_），形状不变 → 图可复用。
  · 单一持久 torch.Generator（register_generator_state 进图），每图 manual_seed 重置。
  · 每个图 load 只写缓冲（约 n_max×cap 个元素），实测 6 ms。
  · 解码仍用捕获版 A.3（chunk=4），再对前 n 行 packbits。
  · 过冲安全：收敛后 where(gain>0, 1-x, x) 不动状态，多跑是 no-op。

闸门（models/check_padded_capture.py）拆成两条事实，因为 spmm 的行内归约顺序不可消除：
  · capture replay vs padded eager：**逐位相等**（60 步状态/档案/解码 bitset），硬断言。
  · padded vs 未 padded：只报 drifted_nodes 与 |Δsize| ≤ 1（实测 drifted 66–178，
    解大小全部一致；spmm 差 8.94e-08、logits 差 1.72e-05）。

必须单进程：4 分片并发时 0.05 s 档只走 0–5 步、1.0 s 只到 650–900 步
（kernel 发射被串行化）→ 所有摊薄数字都是 SHARDS=1 独占 GPU1 跑出来的。

5. 平台 PAVE：增益是输入次优程度的函数（诊断性结论）
------------------------------------------------------------------
机制：PAVE = repair（size+1 交换）+ extend + 学习排序器（PAVEV3）选择候选，
      预算内反复 outer_rounds 轮；它只能修「还没到局部最优」的解。

实验（100 图，同一套 PAVE 超参，只换输入）：

  输入                     输入 SIZE   PAVE 后   增益 [95% CI]              胜/平/负
  最小度贪心               18.3800     19.0900   +0.7100 [+0.5600,+0.8700]  53/47/0
  我们 0.5 s 捕获搜索      19.8750     19.8750   +0.0000                    0/100/0
  KaMIS 0.1 s              20.0500     20.0500   +0.0000   [0,0]            0/100/0
  （KaMIS 六臂：extend/pave/rule/random/long 全部 +0.0000，三个 PAVE 臂
     exchanges 均值 0.00、100/100 图零次交换，extend_gain 0.0 —— 已是极大集）

排序器本身的价值（只在弱构造器启动时可见）：
  学习 19.0900 vs 规则 18.9300：+0.1600 [+0.0800,+0.2500] 15/84/1
  学习 vs 随机 18.9500：        +0.1400 [+0.0700,+0.2200] 14/85/1
  规则 vs 随机：                −0.0200 [−0.0800,+0.0300] 2/95/3

结论：**PAVE 不是 solver-agnostic**。它是「把未收敛的解修到局部最优」的算子，
      增益随输入收敛程度单调下降（0.710 → 0.222 → 0.000）。
      论文里不能写成「接在任何求解器输出上都能 +」。

------------------------------------------------------------------
6.1 九条方法线（v1–v7 全部归档，最好可复现值 0）
    static prior / structure / frequency 交换 / v7 context（TCCR）等，
    详见 models/README.md「已关闭线」与 docs/temporary/RLNN_v7_TCCR_Results.md。

6.2 P0 闸门（v8 宏步 ACMD 线）
    h=2 的联合似然对最终解大小无信号：−0.017/−0.014/−0.008/−0.031，四格 CI 全跨零；
    full vs endpoint 档案：能量 +0.0040[+0.0017,+0.0067]、大小 0[0,0]。
    → 按预注册判读表在训练前停止主线（省下数天 GPU）。见 RLNN_v8_P0_Results.md。

6.3 速度工程到头（捕获 + 解码 + 缓存）
    0.5 s：eager/eager 19.640 → captured/cached 19.920（+0.280）；
    1.0 s：19.775 → 20.010（+0.235）。
    其中解码搬进图块 +0.045/+0.010、跳过重复解码 +0.000/+0.010。
    **700 步之后每翻倍步数只值 +0.01** → 继续堆步数无意义。
    见 RLNN_v8_Positioning_Results.md。

6.4 重训（抬上限）——三条都负
    冻结骨干步数曲线（120 图）：100 步 19.3917 / 300 步 19.6917 /
                                1000 步 19.8083 / 3000 步 19.8667。
    微调 ft_tp50：19.4083 / 19.6500 / 19.8000 / 19.8750（几乎重合）；
    微调 ft_tp300：19.3583 / 19.6333 / 19.7500 / 19.8417（更差）。
    valid_obj：基线 19.52–19.53，ft_tp50 19.53→19.56，ft_tp300 19.47→19.40。
    贪心初始化：30/100/300 步 = 18.7583 / 19.1750 / 19.4417（比随机低 0.45–0.56）。
    从零训练（num_tp=300、30 epochs、1000 图、2.4 h）：valid_obj 18.92。
    原因：erdoes 损失只做**一步前瞻**（flipped=(1-p)x+p(1-x) 的能量 +
          λ(E[#flips]−5)²），不奖励逃出局部最优。见 RLNN_v8_Retrain.md。

6.5 重组与调度（逃逸）
    König 精确重组（打在 0.5/1.0 s 上）：+0.0617 [+0.0483,+0.0753] / +0.0240 [+0.0170,+0.0317]。
    把 PAVE 交换插进搜索循环（inject/refill）：30 图探针 +0.033 / 0.000 / −0.100。
    随机踢动（删 5% 再补）：+0.067 / −0.033 / 0.000 / −0.033。
    → 20 个粒子的档案并集已经是「1-flip + (2,1)-swap 双邻域都空」的局部最优。
    见 RLNN_v8_Retrain.md §6。

6.6 跨族/跨规模迁移（换 regime）
    RB_small_val −0.075[−0.175,0.000]；ER_200_300 −0.625[−0.900,−0.325]；
    BA_200_300 −1.775[−2.200,−1.400]；RB_large −3.625[−4.000,−3.250]。
    ER-[700-800]（128 图，p=0.15）：1.0 s 42.1771 vs KaMIS 44.00 / RLSA 44.10 / RLNN 43.34。
    → 冻结策略只在训练分布上成立，退化随距离单调。见 RLNN_v8_Regime_Probe.md。

7. 明确不主张的边界（写论文时必须写进 limitations）
------------------------------------------------------------------
· 不主张 SIZE 超过 KaMIS（20.106）或 RLSA（19.97@0.07 s）。
  在 1.0 s 档我们 19.983，比 KaMIS 低 0.12，比 RLSA 的同钟插值高但慢 14 倍。
· 不主张两个组件可相加：捕获与平台是替代关系（§5）。
· 不主张跨图族/跨规模泛化：ER、BA、n≈1000 全部退化（§6.6）。
· 主表只有搜索种子 1017（三种子 CI 待补）；单机单卡。
· KaMIS 的 TIME 含进程启动 + 图写盘约 1.87 s/图，所以「0.5 s 以下只有我们能交解」
  是框架地板差异，不能作为卖点。
