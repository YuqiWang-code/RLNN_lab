## 3. 判读（写给 t3，不要复述错）

**(1) 「有效感受野 = 1 跳」被证伪，但也没有到 5 跳。**

- R² 从 0.8426 → 0.8617 → 0.8721：`c2`、`c3` 都还有**真实但很小**的增量解释力（残差方差 15.7% 里，
  `c2` 多解释 12.2%、`c3` 再多 6.6%）。所以策略不是 `(x_i, 邻居选中数)` 的一跳闭式规则。
- 影响量是**整跳聚合**（把该跳所有节点一起翻），不是逐节点权重：RB 小图上 2 跳环覆盖的节点数比 1 跳环
  大一个量级，因此逐节点权重约为 1 跳的 **1/20 量级**（估算，非实测）。这条口径必须写清，别把
  51.7% 误读成「2 跳和 1 跳一样重要」。
- hop-4/5 与「>5 跳对照组」到 10⁻² 以下，**有效深度 ≈ 2–3 跳**，5 层结构确实用不满。

**(2) 平台机制的第一条解释要换。** 诊断文档 §2.5 把「20 个粒子共享单个不动点」归因于「1 跳感受野 +
归一化均值聚合」。G1 说策略看得到 2–3 跳，那么不动点更可能来自**优化轨迹本身的吸引子**
（一步前瞻目标 + 高温消退后策略坍缩到同一模式 + 无记忆逃生算子），而不是架构表达力截断。
这不削弱平台结论（平台已被三种独立方式测到），但**削弱「加跳数」这一整类补救**。

**(3) 对 C2（3 跳加性残差）的判决：降级，不是放行。**

- C2 的原论证是「策略只等价于 1 跳，所以显式补 3 跳是净增信息」。现在实测 2 跳已有半量影响、
  3 跳还有 13.6%，**显式补 3 跳的净增信息远小于原估**（R² 侧只值 ~1–2 pp）。
- 因此 C2 的天花板应从诊断文档的 +0.05 下调到 **+0.02 量级**，且必须先用一个不训练的探针证明
  「残差特征能把 R² 从 0.872 提到 ≥0.90 或把 logit 解释残差砍半」，才值得进训练。
- 若做不到 → **C2 直接关**，不要烧 GPU。

## 4. 由此对 t3 的硬要求（队长裁决）

1. 方向锁定文档必须**显式引用本文件的三个数**（R² 三点、hop 影响曲线、>5 跳对照），并把「1 跳」的
   表述改成「有效深度 2–3 跳、逐节点权重几何衰减」；若沿用旧表述，视为未审查。
2. 生态位重排：**主攻不再默认 C2**。优先级改为
   `C3（size-aware unroll 训练目标，病因明确、与感受野无关）` >
   `P（第二创新点：条件化修复 + 闭包缺口诊断，命题 R / P1–P3）` >
   `C1（两段式粒子预算，保底 +0.02）`；
   C2 降级为「只在残差探针通过后才有资格进矩阵」。
3. 目标口径：诊断文档已指出 20.10 的两个来源互相矛盾（`README.md:28` 20.1060@1 s vs
   `Paper_Table` 20.1020@3.046 s）。锁定文档必须**二选一并写死**，且给出对应的**增速要求**
   （+0.0335 ≈ 34/1000 图各 +1 点）。若 C2 关闭后 1 s 天花板只有 ~20.09，就**不要**把「越 20.10」
   写成 v11 的唯一成功判据——改写成「(i) C3 使 1 s 与 0.2 s 同时改善且 CI 不含 0；或 (ii) 命题 R 的
   P1/P2/P3 至少两条过判据」，否则这一轮注定写「未达标」。
4. 环境阻断解除（供参考，别再当阻塞写）：两个权重在服务器上**都在**
   （`outputs/v2/none_seed0/checkpoints/best.pt` 668 801 B、`outputs/v3/stats_h1_seed0/checkpoints/best.pt`
   18 225 B，合计 <0.7 MB，scp 即回本地）。本地 **不要**试图跑：本机只有 GTX 1650 4 GB、torch 2.9.0+**cpu**、
   无 PyG；所有探针/评测在服务器 GPU1 跑。
