# RLNN v7 · TCCR 第一阶段普查结果

**预注册判决是 `stop`（G2/G3/G5 未过，G1/G4 过），但普查把 TCCR 拆成了两半，结论不一样：**

- **轨迹重组这一半成立且可复现**：三个骨干/PAVE 种子上，把 K=20 个 A.3 合法解做精确二部图重组，在**冻结 PAVE 之上**还有 **+0.088** 个节点（900 次图级配对里 **69 胜 231 平 0 负**）。量级与 PAVE 自己的 +0.096 相当。
- **冲突释放区域这一半不成立**：`|U| ≤ 4` 的联合释放区域在 PAVE 输出上只有 **+0.043**，命中 **8–15/100** 图，且其中的大部分本来就被 PAVE 拿到了。

所以这条线要么按预注册停止，要么收窄为「多轨迹精确重组作为冻结 PAVE 的前置后处理」。**这是需要决策的分叉，不是已经自动确定的方向。**

## 1. 协议

| 项 | 值 |
| --- | --- |
| 数据 | `RB_small_val` 前 100 图（冻结验证集，未碰作者测试集） |
| 骨干 / PAVE | `outputs/v2/none_seed{0,1,2}`／`outputs/v3/stats_h1_seed{0,1,2}`，全部冻结 |
| 搜索 | K20 / T100 / FP32 / A.3 解码，与 `eval_v3` 同口径；每图 3 个搜索种子（1017/1019/1021） |
| 主判决 | ref0；ref1/ref2 为独立复制（不参与门槛判定） |
| 新增计算 | 只有重组与区域枚举；PAVE 的参数、步数预算、候选上限一律不动 |

两条动作的定义：

- **重组**：`I = S_i ∩ S_j`，`L = S_i \ S_j`，`R = S_j \ S_i`。`G[L ∪ R]` 是二部图，`α = |L| + |R| − ν`（König），输出 `I ∪ T*`。对 `S_i ∪ S_j` 而言是**精确最优**，对两张父解单调不劣。
- **区域**：`R(U) = {v ∉ S : B(v) ⊆ U}`，窗口 `W(U) = U ∪ R(U)`，局部精确 MIS。`R(U)` 与 `S \ U` 无冲突，所以合并解合法、且 `|T*| ≥ |U|`。

## 2. 端到端结果（主表）

100 图 × 3 搜索种子，图级先平均再配对，bootstrap 2,000 次：

| ref | B+A.3 | ＋PAVE | ＋重组 | 重组＋PAVE | 重组对 A.3 | **重组在 PAVE 之上的边际** |
| --- | ---: | ---: | ---: | ---: | --- | --- |
| 0 | 19.5467 | 19.6267 | 19.6467 | **19.6967** | +0.100 [0.063, 0.143] | **+0.070 [0.040, 0.103]**，18/82/0 |
| 1 | 19.4967 | 19.6033 | 19.6600 | **19.7067** | +0.163 [0.113, 0.210] | **+0.103 [0.070, 0.137]**，28/72/0 |
| 2 | 19.5433 | 19.6433 | 19.6667 | **19.7333** | +0.123 [0.083, 0.170] | **+0.090 [0.057, 0.127]**，23/77/0 |
| 均值 | 19.5289 | 19.6244 | 19.6578 | 19.7122 | +0.129 | **+0.088**，69/231/0 |

读法：

1. **方向一致、CI 全部跨零之外、900 次配对零负例。** 这不是单种子波动，也不像结构补偿那样在 1.8σ 上反复。
2. **边际收益与 PAVE 自身同量级**（本轮 PAVE 实测 +0.096），但两者**可叠加**：`B+PAVE` 19.6244 → `B+重组+PAVE` 19.7122。
3. 重组是**单调**算子（`|S_new| ≥ max(|S_i|,|S_j|)`），所以"负例为 0"是构造保证，不是运气；真正的问题是**能不能找到有收益的那一对**。

## 3. Phase 1：重组到底能拿多少、多贵

| 指标 | ref0 | ref1 | ref2 |
| --- | ---: | ---: | ---: |
| 20 个解的去重数 | 20 | 20 | 20 |
| 20 个解的平均大小 | 18.359 | 18.359 | 18.412 |
| 20 个解的并集大小 | 139.0 | 138.2 | 136.0 |
| 两两 Jaccard 均值 | 0.093 | 0.098 | 0.100 |
| 190 对里的 Oracle 增益 | +0.100 | +0.163 | +0.123 |
| 其中 **能赢过最好单解** 的对数 | 0.57 / 190 | 1.16 / 190 | 0.57 / 190 |
| 每对耗时 | 304 µs | 313 µs | 313 µs |
| 跑满 190 对 | 58 ms | 59 ms | 60 ms |

机制与成本：

- **收益来自差异区较小一侧的匹配亏空**：`gain = |R| − ν`。绝大多数解对的差异区存在完美匹配（增益 0），只有约 0.6–1.2 对能赢。所以"借一个解里的节点再补回来"这件事本身就很稀有。
- **选对是难点**：固定 8 次调用下，随机 / Hamming 最大 / Size 最优 / 匹配代价最小四种排序分别只拿到 0.020 / 0.027 / 0.037 / 0.013（同口径下 oracle 是 0.100–0.163）。**廉价启发式基本一无所获。**
- **穷举反而便宜**：190 对全跑只要 ~58 ms（纯 Python，未优化）。也就是说这个算子不需要学习型选对，代价是每图几十毫秒。

## 4. Phase 2：冲突释放区域不存在

`|U| = 2/3/4` 的全枚举，精确局部 MIS（窗口 ≤ 60 节点，超限退化为贪心并标记 `exact=0`）：

| 层 | k=2 | k=3 | k=4 | 合并（取 k≤4 最大） |
| --- | ---: | ---: | ---: | --- |
| A.3 解（无 PAVE） | +0.020，6 图 | +0.063，19 图 | +0.097，29 图 | — |
| **PAVE 解** | **0.000，0 图** | **+0.010，3 图** | **+0.030，9 图** | **+0.030 [0.010, 0.053]，8 图** |
| PAVE 解（ref1） | — | — | — | +0.050 [0.027, 0.073]，15 图 |
| PAVE 解（ref2） | — | — | — | +0.050 [0.027, 0.077]，15 图 |

- **PAVE 把区域通道几乎吃干净了**：A.3 层 `k=4` 有 29 图可改善（+0.097），到了 PAVE 输出只剩 9 图（+0.030）。PAVE 的平台搜索本身就是在这类邻域里找的。
- **方案点名的 3→4 动作确实很稀有**：`gain_3 ≥ 1` 只有 3/100 图（门槛要求 ≥ 10）。
- 区域枚举本身很贵：每图 **1,764 ms**（P95 3,353 ms），比重组贵 30 倍，收益小 3 倍。

结论：**方案 B（冲突超图局部重优化）在当前形态下应当放弃**，不是"学不到"，是"不存在"。

## 6. 必须承认的限制

1. **G2 的门写错了性质**。它把"算子成本"和"选对成本"合成一门，隐含假设是"只能调用少数几次"。实测穷举 190 对只要 58 ms，所以正确的成本问题是"穷举 × 58 ms 值不值"，而不是"8 次调用里能不能选对"。**按穷举口径重组是通过的**（0.30 ms/对 ≤ 2 ms/对）。这一条是**事后**观察，明确标注为对预注册的偏离，不改判决。
2. **只有固定工作量结论**。0.5/1.0 秒预算下，58 ms 会挤掉约 1/8 的搜索时间（按本轮 PAVE 240 ms、搜索 ~3.5 s 的实测比例估算），是否仍为正**未测**。方案里的强对照 `B 持续搜索 + PAVE` 也**未跑**。
3. **只到验证集**。作者 1,000 图、跨分布（BA/ER）、K>20 都未测。
4. **新颖性有限**：独立集的最优交叉是 Aggarwal–Orlin–Tai（1997），多解 Difference-Core 是 CHILS（SEA 2025）。这里能主张的是"在 RLNN 的 K 粒子轨迹上做精确重组、给出单调性与实测增益"，不是新算子。

## 7. 过程中修正的一次口径错误

第一版 `best_recombination` 报告的是**每对自己的增益**（相对那一对里更好的父解），不是相对**全局最好的单解**。结果是 +0.803 的假象：一对 20/20 的解重组成 21，相对父解是 +1，但完全没超过 A.3 的最优解 21。

修正后同一批数据是 +0.100。已在 `models/check_v7.py` 里加了回归断言 `best_candidate.bit_count() - max(sizes) == gain`，并把这个口径写进 4.2 的表格。**如果不修这个 bug，这条线会被误判成 +0.80 的突破。**

## 9. 建议的下一步（按投入产出排序）

1. **先补预算门**（唯一能杀死或救活这条线的一步）：0.5 秒与 1.0 秒下 `B 持续搜索 + PAVE` vs `B 持续搜索 + 重组 + PAVE`，重组必须从同一个截止时间里扣。若预算下边际仍为正，重组可以作为一个"免费的确定性前置步骤"进论文；若为负，整条线结束。
2. **把重组算子从 58 ms 压到个位数毫秒**：190 次小规模匹配在 C++/numpy 里是毫秒级；只有压下来，预算门才有胜算。这是纯工程，不改数学。
3. **只在这一步之后再考虑选对模型**：当前 0.6/190 的对有收益，穷举已经够便宜；学一个排序器要证明能超过穷举的收益/成本比，门槛很高。
4. **区域通道不要再投**：除非换成完全不同的区域生成方式（例如按 PAVE 决策轨迹的不稳定性而不是固定 `|U| ≤ 4` 的阻挡集合），否则 +0.04 的量级不值得。
5. 若最终只保留重组：论文形态是"PAVE 之前加一个精确、单调、可证明不劣的轨迹重组步骤"，实验要补 0.5/1.0 秒、1,000 图、K 扫描与跨分布。
