## 0. 结论先行

1. **平台不是「搜得不够」，是三重邻域的共同局部极大。** 1-flip 闭包、k≤4 交换闭包、破坏-修复闭包
   （PAVE 的平台搜索本质上是第三重的一个更强实现）作用在同一个 1 s 解上都不再产生 +1；三次尝试零例外
   （`RLNN_v8_Exchange_Headroom.md`、`RLNN_v10_Move_Set.md`、`RLNN_v8_PAVE_External_Results.md`）。
   这解释了为什么「加步数 / 加粒子 / 加温度 / 加记忆 / 加重组」全部是 0 或负：它们只改**到达**该极大的路径。

   不是「后处理提升」，而是「**输入条件化的修复算子 + 闭包缺口诊断器**」——这是第二创新点唯一站得住的形态。
3. **越过 20.10 只需要 3.4% 的图各多 1 个点**（+0.0335 × 1000 ≈ 34 张图）。这不是「再挤 0.03」的工程问题，

## 2. (a) 平台物理：为什么 1 s 解是三重不动点

### 2.1 先把「不动点」定义清楚

一个解 S 是**算子邻域 N 的不动点**，当且仅当：对 N 内所有移动 m，S⊕m 的解大小 ≤ |S|。
这里要区分两件事，否则会误读所有结果：

- **系统在动**。策略仍在以 1.70%–2.18% 的翻转率每步改状态（`RLNN_v9_SOTA_Hunt.md` §4，3 图实测：
  4.1/5.3/5.0 点/步），密度从第 50 步到第 250 步几乎不变（0.091→0.089、0.095→0.097、0.099→0.095）。
- **档案不再变好**。`models/mis_v8_pad.py:224-237` 的 `_body()` 只在 `energy < best_energy` 时更新
  `best_states`；800 步后这个布尔几乎不再为真。

所以「平台」= 状态在闭包内游走、档案卡在同一个局部极大。下面三重是分别测的。

### 2.2 第一重：1-flip 闭包

**主张**：1 s 解在「翻转任一节点」的邻域里是不可改进的；能改进它的点是极少数且被锁死。

| 证据 | 数字 | 来源 |
| --- | --- | --- |
| 被恰好一个已选点挡住的自由点（ones/exact） | 0.2 s：29.57；1.0 s：28.00——很多，但**两两相邻**，凑不出 (1,2) | `RLNN_v8_Exchange_Headroom.md` §2 |
| 密度轨迹在 50 步后不动 | 三图 0.091/0.095/0.099 → 200 步后 0.089/0.097/0.095 | `RLNN_v9_SOTA_Hunt.md` §4 |
| 档案能量单调不增且饱和 | 244 步 20.0235 / 397 步 20.0420 / 808 步 20.0685 / 1729 步 20.0610 | `README.md:77-86` |
| 每翻倍步数只值 | 700 步后 +0.01~0.03 | `README.md:57`、`RLNN_v8_SOTA_Direction.md` §1.3 |

关键推论（`RLNN_v8_SOTA_Direction.md` §3 D1）：翻转节点 i 的收益只看 1 跳（i 的占用），代价看 2–3 跳
（冲突边的另一端点及其邻居）。而主干是 5 层 128 宽**归一化均值** GCN（`models/models.py:46` 的
`deg^{-1/2} A deg^{-1/2}`、`models/models.py:129-135` 的 `x = relu(nei + Wx) + x`、`models/models.py:74`
的 `spmm`），最大出度 104、平均度 d≈80（`padded_ref0.json` nodes=264 capacity=105，`models/eval_v8_padded.py`
的 `shape_of`），信号按 d^{-(k-1)/2} 衰减：1 跳 1 / 2 跳 ≈1/9 / 3 跳 ≈1/80 / 4–5 跳 ≤1/700。
**所以策略在信息上近乎是 (x_i, 选中邻居数) 的确定性函数，同一个 (x_i, k_i) 必然给同一个动作 → 唯一不动点。**

注意这条是**推演**，不是测量：`models/probe_receptive_field.py` 就是为它写的（G1），但从未运行
（无 `outputs/v8_macro/receptive_field/`）。且 `RLNN_v8_Global_Token.md` §3 的作者判读与它相反
（「5 层在 250 节点平均度 38 上已覆盖 2–3 跳」）。**这是本文件最大的未决项，见 §7。**

### 2.3 第二重：k≤4 交换闭包

**主张**：把「删 1 加 1/2、删 2 加 2/3」以及 k≤4 的一般 k→k+1 交换全部枚举，1 s 解上一个可用的
+1 见证都没有。这比 1-flip 强得多：1-flip 只否证「单位置替换」，交换允许「牺牲一个换两个」。

| 证据 | 数字 | 来源 |
| --- | --- | --- |
| 20 图冒烟（1.0 s，PAVE 19.7000） | k2/k3/k4 = 0/20、0/20、0/20 | `RLNN_v8_Exchange_Headroom.md` §2 |
| 60 图全扫（1.0 s，PAVE 19.8833） | k1/k2/k3 = 0/60、k4 = 0/60（干净全零） | 同上 |
| 60 图全扫（0.2 s，PAVE 19.7500） | k1/k2/k3 = 0/60、k4 = **1/60** | 同上 |
| 正对照（最小度贪心起点） | k1 2/6、k2 3/6、k3 3/6；单图最多 k3:30 | 同上（证明探针找得到见证） |
| König 精确重组（`models/mis_v7_recombine.py`）在 80 个去重档案解上 | **增益恰好 0**（22→22、19→19），17–75 ms/图 | `RLNN_v10_Move_Set.md` |
| RLSA 独立实现，200 粒子档案的 oracle | best_single 19.85 / chain 19.90 / oracle 19.85 → **+0.000** | `RLNN_v10_Move_Set.md` |
| v7 TCCR 历史 | K=20 重组 +0.088（69/231/0）但预算门四格全跨零 | `README.md:44-65` |

第二条特别重要：**RLSA 200 个粒子、独立代码库、独立种子，精确重组 oracle 也是 +0.000**。
一个独立实现的种群都重组不出 +1，说明这不是「我们的档案太同质」，而是**这一层邻域在该解附近真的空了**。

### 2.4 第三重：破坏-修复闭包

**主张**：把「破坏一个球、再修复回来」作为移动，1 s 解也动不了；而且修复会把解**送回原处**。

### 2.5 为什么三重会同时成立（机制，不是巧合）

三条事实拼起来只有一个解释：

1. **三个算子都在同一个 Lyapunov 函数上单调上升**。`models/mis_v3_search.py:277 rollout` 明确
   「best 单调、rolled_back 时回 best」；`:247 repair` 只取 `actions[0]`；`models/mis_v10_lns.py`
   的 `restore=True` 在 `on_block` 里 `engine.state.copy_(engine.best_states)`。
   于是「破坏-修复」不是逃逸，而是**回到同一个局部极大的另一条路径**——周期 10 逐位相同就是这个的签名。
2. **能量不进采样动力学**。`models/mis_v8_pad.py:224-237` 用 `energy < best_energy` 只决定**档案入选**；
   采样只看 `probs = sigmoid(logits/T)`。所以 `beta` 从未被扫过也从不影响轨迹
   （`RLNN_v9_SOTA_Hunt.md` §4 明确指出）。温度只改噪声幅度（`RLNN_v8_Learned_Annealing.md`：
   T=4 −0.37、T=8 −0.68），不动不动点。
3. **所有逃生算子都无记忆**（`RLNN_v8_SOTA_Direction.md` §3 D3）：踢动（`Retrain`：−0.033）、
   温度、策略重填、球内修复、PAVE，全都在下一轮被同一个确定性映射吸回去。
   文献里的逃生机制（tabu tenure、configuration checking FastVC IJCAI 2015 / TIVC Sensors 2023、
   动态边权、breakout、1RSB reweighting）**全部带记忆**，这不是巧合。

一句话总结（可直接进论文）：**1 s 内的解是 1-flip + (2,1)-swap + 破坏-修复 三重邻域的共同局部极大；
策略是一个只看得见 1 跳的确定性映射，因此三重邻域共享同一个吸引子，而不是三个互相独立的平台。**

## 3. (b) PAVE 为什么只剩 +0.004

### 3.1 三个点和一条曲线

| 输入 | 输入解质量 | PAVE 之后 | 增益 | 交换数 | 来源 |
| --- | --- | --- | --- | --- | --- |
| 最小度贪心 | 18.3800 | 19.0900 | **+0.710 [+0.560,+0.870]** 53/47/0 | 大量 | `RLNN_v8_PAVE_External_Results.md:29-88` |
| 我们 eager 0.5 s | 19.3560 | 19.5780 | **+0.222** | 中 | 同上 |
| 我们 captured 1 s | 19.9293 | 19.9333 | **+0.0040** | ≈0（1058 步，60% 时钟被吃掉） | `RLNN_v8_Paper_Table.md:30-52` |
| KaMIS 0.1 s | 20.0500 | 20.0500 | **+0.000 [0,0]** 0/100/0，六臂全 0 | `RLNN_v8_PAVE_External_Results.md:29-88` |

三个数字同源：**PAVE 的平台搜索（`models/mis_v3_search.py:340 platform_search`）本身就是一个完备的
「交换 + 破坏-修复」闭包**。它能把一个 2 点缺口修满，也能把 0.6 点缺口修到 0.01，但修不了 0 缺口。

### 3.2 增益的分解式（可测，不是比喻）

把 PAVE 的增益写成两个可分离因子的乘积：

```
G(start) = C(start) × R(start)
C(start) = 闭包缺口 = size(platform_search_无预算(start)) − size(start)      # 修复算子能走多远
R(start) = 选择器效率 = G(start) / C(start)，≤ 1                            # 预算内的实现率
```

已有数据可以分别估出这两个因子：

- **C 主导**：贪心起点 C≈0.71，我们 0.5 s C≈0.22，1 s 与 KaMIS C≈0。
- **R≈0.9 且已经很高**：贪心起点上 learned 19.0900 vs rule 18.9300（+0.1600 [+0.080,+0.250] 15/84/1）
  vs random 18.9500（+0.1400）；rule−random = −0.0200（2/95/3）。
  即：**「做修复」本身值 +0.55，「学排序」只再加 +0.16，随机排序等于规则排序。**
  这条直接否证了 v3 线的定位（PAVE-Stats H1 只比 rule23 高 +0.0603，`README.md:44-65`）。
- **1 s 档 C 的实测上界是 0**：`exchanges 均值 0.00`、`100/100 图零交换`、`extend_gain 0`
  （`RLNN_v8_PAVE_External_Results.md`）。注意 `deadline_hit 50/100`（learned）、41/100（rule）、
  29/100（random）说明 PAVE **不是被预算饿死**，而是整整 0.066 s 里找不到一个可做的交换。

### 3.3 把「PAVE 在什么输入条件下还有价值」变成三个可测命题

**P1（定律：增益是闭包缺口的单调函数）**

> 命题：存在一条质量阶梯 S_0 ≺ S_1 ≺ … ≺ S_k，使 G(S_i) 与 C(S_i) 同序，且 G/C ≥ 0.6。

- 协议：同一批 100 张验证图、同一 PAVE checkpoint（`outputs/v3/stats_h1_seed0/checkpoints/best.pt`，
  horizon=1）、预算 0.1 s。阶梯用**现成的东西**拼：随机 50%、最小度贪心（18.38）、我们 0.05/0.1/0.2/0.5/1.0 s
  五档捕获解、KaMIS 0.1 s。C 用无预算的 `platform_search(deadline=inf)` 算。
- 判据（成功）：Spearman(G, C) ≥ 0.8 且回归斜率 ∈ [0.6, 1.1]；六个点里至少两个 C > 0.1。
- 判据（死刑）：G 与 C 无关（ρ < 0.3），或所有 C > 0.1 的点 G < 0.2·C。
- 成本：修复侧 0 GPU（全 CPU 位运算，`models/mis_v3_search.py` 现成）；输入解优先复用
  `outputs/v8_macro/pave_external/`、`outputs/v8_macro/positioning/` 的 CSV，缺档位再用捕获引擎补
  100 图（≤10 min）。合计 ≤ 4 h。
- 这一条不是新实验，而是**把已散落的四个数字补成曲线**；它一旦成立，PAVE 的贡献就从「+0.004」变成
  「一个可预测的量」——这是论文里能写的那句话。

**P2（预算：在低时钟档还有价值，在 1 s 档应该让位）**

> 命题：0.2 s 档 PAVE 的边际收益 > 同等时间给搜索的边际收益；1 s 档相反。

- 协议：0.2/0.5/1.0 s 三档，各做三个臂：`PAVE-off`、`PAVE-on（reserve 0.1 s）`、
  `PAVE-off 但搜索多 0.1 s`。1000 图、图级配对自助（`models/compare_v8_runs.py`）。
- 判据（成功）：0.2 s 档 PAVE-on ≥ +0.03，且 >「多 0.1 s 搜索」臂；1 s 档 PAVE 让位不掉分（≤ −0.005）。
- 判据（死刑）：0.2 s 档 ≤ +0.01（即低时钟档也没有价值 → PAVE 只能当诊断器，不能当组件）。
- 成本：1000 图 × 3 档 × 3 臂 ≈ 1.5 h GPU（复用 `models/eval_v8_padded.py`）。
- 依据：0.2 s 只有 414 步、搜索边际 0.01–0.03/翻倍（`README.md:57`），而 PAVE 在次优输入上单次修复
  能做到 +0.22；这是算术上唯一还可能赢的档位。

**P3（诊断器：用 PAVE 的增益反过来预测解的质量/所需预算）**

> 命题：用一个便宜的前向（≤5 ms）预测「这张图还差多少」，R² ≥ 0.3。

- 协议：输入 = 当前解 + 图统计（24 维 stats，`models/mis_v3_value.py` 现成），标签 = P1 的 C；
  训练集用 800 张合成/验证图，测试 200 张。
- 判据（成功）：R² ≥ 0.3，且用它做「是否修复」的门控能省 ≥ 30% 时钟不掉质量。
- 判据（死刑）：R² < 0.1（则 PAVE 连诊断价值都没有，整条线彻底关）。
- 成本：≤ 2 h（小 MLP + 已有 stats）。
- 价值：这条即使 P1/P2 都成立也值得做——它把「后处理」重写成「**算子完备性度量**」，
  是审稿人问「你怎么知道什么时候该修复」的唯一答案。

### 3.4 为什么「后处理」这条路本身也快没了

- PAVE 吃 KaMIS 解 = 0（`RLNN_v8_PAVE_External_Results.md:29-88`）：外部强解上也修不动。
- in-loop PAVE 在 1 s 内 0 exchanges、吃 60% 时钟（`RLNN_v8_Retrain.md`）：放进环里更差。
- 交换进环（0.1/0.2/1.0 s）：−0.021/−0.036/−0.055（`README.md:98-121`）。
- v8 interleave inject（0.05 s 起点注入）：+0.0240（39/943/18），但 0.1–1.0 s 全负（−0.021/−0.036/−0.055，同上）。

**所以 PAVE 不能作为「末端 +0.004 的后处理」存在，只能作为「条件化修复算子」存在。**

### 3.5 结论：PAVE 的正确命题（第二创新点）

> **命题 R**：修复类后处理的增益由输入的闭包缺口决定，而不是由排序器的表达力决定；
> 因此一个可部署的修复模块必须（i）估计缺口（P3）、（ii）只在缺口 > τ 时被调用（P2 的调度）、
> （iii）在缺口大的输入上换掉算子本体而不是换排序器（§2.7 第三行）。

这三件事都有现成代码（`platform_search`、24 维 stats、`mis_v10_lns` 的 evict/release），
且都能在 CPU 上完成大部分验证。这是整个 v11 里**风险最低、最可能变成论文第二段**的一条。

## 4. (c) 七个候选方向

每个都按同一模板写：机制一句话 / 文献依据 / 改码点（文件:行）/ ≤1 天探针 / 成功判据 / 死刑判据 /
GPU 成本 / 风险。探针一律**先做不训练的那一半**。

> **前提（见 §0.6）**：所有探针都依赖服务器上的两个权重
> （`outputs/v2/none_seed0/checkpoints/best.pt`、`outputs/v3/stats_h1_seed0/checkpoints/best.pt`）。
> 本地工作区没有它们；下面的成本估算不含「恢复权重」这一步。

> 文献锚点主要来自仓库已核的 `RLNN_v8_SOTA_Direction.md` §8 清单；2024–2026 CCF-A 的系统检索是
> t1 的任务，本文件不重复，凡我未二次核实的引用都标「待证」。

### C1 两段式粒子预算（宽 → 窄）

- **机制**：前 0.6 s 用 K=200（≈500 步，1.18 ms/步）探索，把档案最好的 20 列 prime 进 K=20 引擎
  （0.329 ms/步），后 0.35 s 再跑 ≈1000 步。同一秒内把「人口宽度」换成「步数深度」。
- **文献**：anytime 资源分配 / 种群大小 vs 迭代数的算法配置结论；直接依据是我们自己的两条端点曲线
  （K=200 808 步 20.0685 vs K=20 2887 步 19.9830，`README.md:77-86`、`RLNN_v8_Amortised_Capture.md`）。
- **改码**：`models/mis_v8_pad.py:174 prime(mask, particle=)` 已支持单列注入；需要第二套
  `PaddedSearch(num_k=20)` 实例 + 挑选逻辑，新文件 `models/mis_v11_ebudget.py`；驱动入口
  `models/eval_v8_padded.py:167-240`。
- **≤1 天探针**：100 图 × 3 种切分（0.5/0.5、0.6/0.4、0.7/0.3）× 2 种选列（最低能量 20 / 解码最大 20）。
- **成功**：1 s ≥ 20.085（越过 RLSA 插值）。
- **死刑**：全部 ≤ 20.070（等于说饱和曲线已经预言了它）。
- **GPU**：100 图 × 6 配置 × 1 s ≈ 10 min。
- **风险**：饱和曲线说每翻倍 +0.01~0.03，K=20 的 1000 步可能只是把 19.98 补到 20.00；
  若选错 20 列（best 列 ≠ 最好盆地），会掉 0.05。**这是唯一「不换算子」还能动 1 s 档的杠杆，但天花板大约 +0.02。**

### C2 3 跳加性残差（hop-residual，DCSS 的加性版）

- **机制**：冻结主干 logits，加一个小残差 `r_i = MLP([x_i, c1_i, c2_i, c3_i, deg_i])`，
  `c_k` = k 跳已选计数 / √E[c_k|deg]（度数补偿）。只训残差（~2k 参数），KL 锚定到冻结策略。
- **文献**：scale-space / 热核算子（`RLNN_v8_SOTA_Direction.md` §5 的 `w_k(τ)=e^{-τ}τ^k/k!`）；
  多尺度 GNN 与 coarsening 的机制对照（arXiv 2609.25149v2，待证）；1RSB 玻璃态图像
  （Dall'Asta PRE 80 061136）说明「同水位」是必然。**注意：v9 DCSS 是同一机制的重版本，实测 −0.71**，
  所以本方向必须证明「加性」不是「替换」。
- **改码**：新增 `models/mis_v11_hop.py`（残差模块）；挂载点 `models/solvers.py:550 flip_logits`
  （在返回前加残差，主干不动）；`models/main.py:45` 的 `--arch` 加 `gcn+hop`；对照实现
  `models/mis_v9_scale.py:72 ScaleSpaceGCN`（只读，用于确认热核形式）。
- **≤1 天探针（第一步不训练，30 min）**：跑 `models/probe_receptive_field.py`
  （`--graphs 10 --targets 20 --hops 5`，写 `outputs/v8_macro/receptive_field/receptive_field.json`）。
  判据：`r2_mean[0] ≈ r2_mean[2]`（加 c2/c3 不提升 R²）且 `influence_mean["3"] ≤ 0.01·influence_mean["1"]`
  → A4 成立，本方向有地基。**这个探针已写好、从未运行。**
- **成功**：1 s ≥ 20.10（越 KaMIS）；中间门 0.2 s ≥ 19.90（+0.06）或验证目标 ≤ −19.65。
- **死刑**：G1 显示 3 跳 R² 提升 > 0.1（则 A4 假，机制不成立）；或残差训练后 1 s < 20.075；
  或残差在部署时 std < 0.05（学到的是恒等）。
- **GPU**：G1 30 min + 6 epoch 微调 40 min + 1000 图四档评测 20 min。
- **风险**：v9 教训是表达力↑但吞吐↓、质量↓；本方向若让每秒步数掉 >5%，收益会被时钟吃掉（808 步是 1 s 的产物）。

### C3 尺寸感知的训练目标（unroll + ST 解码）

- **机制**：目标从「固定 num_d 的期望能量」改成「8 宏步展开后的解码大小」，用
  `problem.decode_gradient_flip` 的 ST 松弛回传，加 KL 锚定。这是把 D2（训练≠部署）直接修掉。
- **文献**：algorithm unrolling 综述（arXiv 2512.03768）、HG-DAgger（1810.02890）、
  DP self-training（NeurIPS 2023 poster 70728）。**现在的 loss 是一步前瞻**
  （`models/solvers.py:29 erdoes_graph_batch_loss`：`flipped=(1-prob)x+prob(1-x)`，`energy_func` 一次，
  惩罚 `(Σprob − num_d)²`），既不奖励解码大小也不看第二步。
- **改码**：`models/solvers.py:29` 旁新增 `size_graph_batch_loss`；`models/main.py:38` 的
  `--loss` 加 choice；`models/solvers.py:391-396` 的分支；展开循环复用 `models/mis_v8_macro.py`
  的 joint likelihood 结构（只读）。
- **≤1 天探针**：1000 图、6 epoch、lr 2e-5、KL 权 1.0，只训 8 步展开策略；验证 obj 与 4 档部署。
- **成功**：验证 obj ≤ −19.62（冻结 19.52–19.53）且 1 s ≥ 20.08。
- **死刑**：验证 obj 不动（v8 Retrain 的三组在四个步数上几乎无差：冻结 19.3917/19.6917/19.8083/19.8667、
  ft_tp50 19.4083/19.6500/19.8000/19.8750、ft_tp300 19.3583/19.6333/19.7500/19.8417，`RLNN_v8_Retrain.md`）。
- **GPU**：≤ 2 h。
- **风险**：ST 梯度方差大；KL 太强等于冻结；v8 从零训练更差（18.92）说明优化面本身难。
  **但这是唯一「改目标」的线，和 C2 正交，可共用一次训练预算。**

### C4 记忆化破闭包（tabu + configuration checking）

- **机制**：LNS 释放后不许立刻回填：tabu tenure 冻结被释放点，CC（顶点的 configuration 不变则不选）
  冻住整个区域，强制跨盆地。
- **文献**：FastVC（IJCAI 2015）、TIVC（Sensors 2023）、两阶段 tabu+进化（SORT 2020）；
  `RLNN_v8_SOTA_Direction.md` §4.5 判「记忆活，排第三」。
- **改码**：`models/mis_v10_lns.py:__init__` 加 `tenure/cc` 参数、`on_block` 加计数；
  引擎侧 `models/mis_v8_pad.py:209 evict` / `:219 release` 已够（`tabu` 是 bool 缓冲，需扩成计数）。
- **≤1 天探针**：20 图 × tenure{8,16,32} × CC{0,1} × 1 s。
- **成功**：≥5/20 图改进且均值 +0.03。
- **死刑**：全部 ≤ +0.01，或又是「逐位回原解」。
- **GPU**：40 min（控制器在 CPU，只有引擎在卡上）。
- **风险**：v10 已证「受禁」本身不迁移（周期 2 不回退 −0.275）；正样本率 0.24% 说明闭包外也未必有解。
  **这是三重不动点里唯一还没测的记忆维度，但期望值不高。**

### C5 盆地多样性 + 精确重组收割

- **机制**：粒子间加 Hamming 惩罚 / 分族用不同初始分布，把盆地分裂开，再用 König 重组收割。
- **文献**：scatter search / island model（§4.8）；v7 的 König +0.088；1RSB 多态图像。
- **改码**：`models/mis_v8_pad.py:174 prime` 分族注入；`_logits` 加多样性惩罚项；

- **成功**：Jaccard < 0.7 且重组增益 ≥ +0.03。
- **死刑**：多样性上去、重组仍 0。
- **GPU**：10 min。
- **风险**：v9 DCSS 已经做过这件事：分散度 ×15（Jaccard 0.0476），质量 −1.78，重组 oracle 只 +0.75 但全被质量损失吃掉。
  **这是期望值最低的一条，只值得当「手术刀」验证，不值得立项。**

### C6 起点族 + PAVE 收割（低成本、直接接 (b)）

## 5. (d) 推荐两条

### 5.1 主攻：越过 20.10（C2 × C3 一条程序，C1 作保底）

**理由**：三重不动点里只有「策略的输入」和「训练目标」两个维度没被堵死（§2.7）。C2 补信息、
C3 改目标，二者共用一次微调预算且互相独立可消融；C1 是「不换算子」的唯一杠杆，天花板 +0.02，
作为 C2 失败后的保底（20.0685 + 0.02 ≈ 20.09，仍不够 20.10 → 所以保底只能保住「离 SOTA 0.01 以内」）。

**三天 Gate（沿用 `RLNN_v8_SOTA_Direction.md` §6 的三天骨架，但只留必要项）**：

| Gate | 内容 | 成本 | 通过判据 | 止损 |
| --- | --- | --- | --- | --- |
| G1 | 跑 `models/probe_receptive_field.py`（从未运行；需服务器权重） | 30 min | `r2(c1)==r2(c1..c3)` 且 hop3 ≤ 1% hop1 | 不成立 → 放弃 C2，转 C1+C3，并把 A4 从论文里删掉 |
| G2 | C2 残差 + KL 微调 6 epoch；0.2 s 单格 | 1 h | 0.2 s ≥ 19.90 | 不动 → 停 C2 |
| G3 | 1000 图 1 s 四档评测 + 图级配对自助 | 20 min | **1 s ≥ 20.10** | < 20.085 → 回到 20.0685 收口，按版本 A 写 |

**成功判据（写论文的那一条）**：1 s ≥ 20.10 且 ≥ 2 个训练种子方向一致（见 §7 单种子问题）。
**死刑判据**：G1 不成立，或 G2 三档（0.2/0.5/1.0）全 ≤ 基线。

### 5.2 第二创新点：把 PAVE 从「后处理」变成「条件化修复 + 闭包缺口诊断」（C1 名，实为 §3.5 的命题 R）

三个可交付物，全部有现成代码：

1. **定律（P1）**：增益 = 闭包缺口 × 选择器效率，四点已测，补成曲线（0 GPU）。
2. **调度（P2）**：0.2 s 档修复、1 s 档让位；把「修复预算」和「搜索预算」放在同一个时钟里比较。
3. **诊断器（P3）**：用 24 维 stats 预测缺口，作为「何时修复」的门控；顺带回答审稿人「为什么不是永远修复」。

**卖点（一句话）**：*修复算子的收益不是常数，而是输入次优度的函数；我们给出可测的度量、可预测的门控，
以及在 1 s 预算下的最优调度。* 这条主张不依赖 SOTA，天然抗「没打过 KaMIS」的审稿意见。

**不做**：把 PAVE 当末端后处理（已死，+0.004）、换排序器（只值 +0.16 且 v3 已试）、
把 PAVE 外接到外部强解（KaMIS 上恰好 0）。

### 5.3 明确不推荐

- **继续加步数/加粒子/加温度**：三条都已饱和（`README.md:98-121`）。
- **精确重组**：80 解档案 +0.000，RLSA 200 粒子 oracle +0.000（`RLNN_v10_Move_Set.md`）。
- **图缩减/coarsening**：RB 图度 ≤3 顶点占比 0%，kernel 88.1% 只取走 1.3 点（`RLNN_v8_Large_Moves.md`）。
- **SDP/Lovász/谱**：θ=Θ(√n) vs α=Θ(log n)，量级就不对（§4.2）。
- **多尺度 backbone（scale/norm）**：v9 已实测质量 −0.71~−0.78（`RLNN_v9_DCSS_Results.md`）。
