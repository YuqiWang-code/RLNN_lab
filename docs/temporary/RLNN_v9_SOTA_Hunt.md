# v9 SOTA 追猎记录（K=200、组合、先验、时钟修正）

本文件记录 2026-11-16 在「超过 RLSA @ 1.0 s ≈ 20.085」这个门槛下的所有尝试。
DCSS 本体（`--arch scale` / `--arch norm`）的判决在 `RLNN_v9_DCSS_Results.md`，
这里只记它之后的杠杆。

## §0 结论先行

1. **组合不是杠杆**：我们与 RLSA 的逐图最优混合，在 1.0 s 内上限 ≈20.08，
   正好卡在 RLSA 单独 1.0 s 的 20.085 之下。
2. **神经引导 RLSA 单调变差**：把冻结策略的 logit 加进 RLSA 的能量梯度，
   w=0.05/0.1/0.2 的 size 依次 19.920/19.870/19.760，且墙钟慢 39%。
3. **K=200 在 1.0 s 首次过 20**（20.0235，1000 图）且**未饱和**；
   代价是每步 ∝ K，步数从 2887 掉到 244。
4. **策略 50 步内进入吸引子**：每步只翻 1.7–2.2 % 的节点（4–5 个），
   密度在第 50 步到 0.091 后 200 步不变 —— 这就是「步数每翻倍只值 +0.01」的机制。
5. **时钟诚实性修正**：`PaddedSearch.run` 的 deadline 曾被异步 replay 绕过
   （`replay` 只入队，不阻塞），不 sync 时循环会跑到 CUDA 队列深度，
   0.05 s 预算实测跑了 9.67 s / 343 块。已改为每块 `synchronize`。
   因此「关掉 decode 后 3861 步、20.45」是**约 10 秒**的结果，不是 1 秒，作废。
6. **真正的成本模型**：每步成本 ∝ K × hidden²（5 层 128 宽的线性层是主项，
   CSR spmm 只占 ~0.1 ms）。据此：dense 邻接 +18 %，fp16 +80 %，
   砍层 ×1.67，砍宽度 ×4（64 宽）/×16（32 宽）。

## §5 时钟修正

`models/mis_v8_pad.py` 的 `run()` 原来只在块之间检查 deadline：

```python
started = perf_counter()
self.graph_exec.replay()
steps += self.chunk
```

`replay` 只把工作入队，`perf_counter() - started` 读到的是**发射时间**（几十微秒），
于是 `perf_counter() + block_time >= deadline` 永远不成立，循环一直跑到 CUDA
队列深度上限。实测（`tmp/probe_deadline.py`，K=200，1 图）：

| 预算 | 修复前 | 修复后 |
| --- | --- | --- |
| 0.05 s | 9.670 s / 343 块 | 0.029 s / 1 块 |
| 0.2 s | 9.694 s / 348 块 | 0.177 s / 6 块 |
| 1.0 s | 10.513 s / 376 块 | 0.978 s / 33 块 |

修复后 1.0 s 的真实步数是 **330**（K=200），不是 3861。
`decode_every > 1` 的旧结果（`k200_prof_nodecode`、`k200_de3b`）因此都不可用；
`decode_every = 1` 的旧结果不受影响，因为每块 decode 会隐式同步。

## §6 成本模型与可用的加速

单步 2.96 ms（K=200、5×128 fp32）。分解：

- 5 层每层一个 `Linear(128, 128)`，作用在 `(264 × 200)` 行上：865 MMAC/层，
  合计 4.3 GMAC ≈ 8.6 GFLOP，按 2.8 TFLOPS 算就是 3 ms —— **主项**；
- CSR `spmm`（27k nnz × 200 列 ≈ 5.4 MMAC）只占 ~0.1 ms；
- 因此成本 ∝ K × hidden²，与层数线性、与宽度平方。

实测加速（`tmp/probe_dense.py`，1 图，K=200，1.0 s 预算）：

| 配置 | 步数 | µs/步 |
| --- | --- | --- |
| fp32 + CSR | 260 | 3708 |
| fp32 + dense | 310 | 3142 |
| fp16 + CSR | 310 | 3239 |
| fp16 + dense | **470** | 2084 |

dense 是对的（`logit max |diff| = 1.6e-05`，fp32 下与 CSR 路径一致）。
fp16 让 logits 的差升到 6.3e-02，但那是两种累加顺序的舍入，不是错误。
