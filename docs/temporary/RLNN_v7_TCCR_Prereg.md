# RLNN v7 · TCCR 普查：预注册与判决门槛

> 本文件在跑任何 v7 实验**之前**写定，用来固定门槛。看到结果后不修改门槛、不改口径、不移动样本集。
>
> 结果见 [RLNN_v7_TCCR_Results.md](RLNN_v7_TCCR_Results.md)。
> 研究方案见用户提供的 TCCR-RLNN 文档；本文只覆盖 v7 的第一件事：**不训练的可达改善空间普查**（Phase 1 轨迹重组 / Phase 2 冲突释放区域）。

## 0. 定位

先回答一个存在性问题：**在 RB200–300 上，冻结 B＋PAVE 的解之外，这两类联合动作到底还能不能变好、变好多少、代价多大。** 若没有足够多图的严格改善，TCCR 不进入训练，也不做模型设计。

两项普查都不训练、不写回搜索，只读：

| Phase | 起点 | 动作 | 精确性 |
| --- | --- | --- | --- |
| 1 轨迹重组 | K=20 个 A.3 合法解 | 二部图差异区最大独立集（König） | 差异区内**精确**，并已与暴力枚举交叉验证 |
| 2 冲突释放 | A.3 解、PAVE 停滞解 | `U` (|U|=2/3/4) → `R(U)` → `G[W(U)]` 精确 MIS | 局部子图**精确**（≤60 节点），否则退化为贪心并记录 `exact=0` |

## 1. 固定协议

| 项 | 值 |

| 数据 | `models/data/MIS_tensors/RB_small_val` 前 100 图（冻结验证集，非测试集） |
| 骨干 | `outputs/v2/none_seed{0,1,2}/checkpoints/best.pt`，冻结 |

| PAVE 后处理参数 | `outer_rounds=8`、`initial_rounds=3`、`horizon=2`、`candidate_cap=32`、`improving_cap=48`、`repair_rounds=4`，`deadline=inf` |
| 不涉及 | 0.5/1.0 秒预算、作者 1,000 图、任何训练 |

## 2. 指标定义

**图级值一律先在种子内平均，再按图做配对统计**，杜绝把 300 个 (图, 种子) 当独立样本。

- `oracle_gain`（Phase 1）：190 个解对全部精确重组后的最大 `|S_new| − max(|S_i|,|S_j|)`。按构造 ≥ 0。
- `arm_*`（Phase 1）：固定 8 次调用预算下，四种选对策略（随机 / Hamming 最大 / Size 最优 / 匹配代价最小）得到的最优解增益。
- `gain_k`（Phase 2）：`|U|=k` 的所有区域中，`α(G[W(U)]) − k` 的最大值。按构造 ≥ 0。
- `improving_k`：同层中 `α(G[W(U)]) > k` 的区域个数（即真实的联合释放改善）。
- `stalled`：PAVE 相对 A.3 起点没有变大的图（方案里"PAVE 停滞"的口径）。
- CI：按图 bootstrap 2,000 次、固定随机种子 20261111 的 95% 分位区间。

## 3. 门槛（写死）

| 门 | 条件 | 含义 |
| --- | --- | --- |
| **G1 重组存在性** | `oracle_gain` 图级均值 **≥ +0.10**；95% CI 下界 **> 0**；`oracle_gain > 0` 的图 **≥ 20/100** | 不是一两个孤立个案 |
| **G2 重组成本** | 每次重组均值 **≤ 2 ms**；固定 8 次调用里 Hamming 臂均值 **≥ 0.5 × oracle 均值** | 便宜，且廉价选对策略能拿到一半以上收益 |
| **G3 区域存在性（PAVE 层）** | `max(gain_2, gain_3, gain_4)` 图级均值 **≥ +0.10**；CI 下界 **> 0**；有改善的图 **≥ 20/100** | 与重组同量级才算值得接着做 |
| **G4 区域成本** | 每图层普查均值 **≤ 2,000 ms**、P95 **≤ 4,000 ms**（离线诊断口径） | 排除"改善只存在于不可算的搜索里" |
| **G5 联合动作（3→4）** | PAVE 层 `gain_3 ≥ 1` 的图 **≥ 10/100** | 方案点名验证的 3→4 动作真实存在 |

补充口径：

- `+0.10` 取自 PAVE 自身在验证集上的量级（+0.10～+0.15）。低于这个数，新模块的收益无法与既有后处理区分。
- 参考量级：KaMIS 在同一批图上是 20.06、B＋PAVE 是 19.62，差距约 0.44。归档的静态先验线里，0.17 的空对照带已经足以判死一个 +0.19 的 oracle。**G1/G3 只验证"存在可达改善"，不验证"限时内能拿到"。**

## 4. 判决表（运行前写定）

| 结果 | 判定 | 下一步 |
| --- | --- | --- |
| G1∧G2∧G3∧G4∧G5 | `advance` | 进入 Phase 3：区域排序＋成本感知调度，按方案做规则的 / 学习的对照 |
| G1∧G2 但非 G3/G5 | `recombine_only` | 第二创新点收窄为"多轨迹精确重组＋解对筛选"，放弃区域 LNS |
| G3∧G5 但非 G1 | `conflict_only` | 收窄为"冲突约束认证＋成本感知大邻域"，放弃重组 |
| 其他 | `stop` | 停止 TCCR；转而诊断全局解差距（KaMIS 0.44 的差距落在哪类图、哪类结构上） |

G4 只否决"成本不可接受"，不单独构成 `advance`。任何门失败都不允许通过调整门槛、换种子、换图子集来"救回"。

## 5. 这次普查不能证明什么

1. **不能证明限时收益**：oracle 是离线口径，0.5/1.0 秒内要多付搜索步数、CPU 时间与 PAVE 预算。
2. **不能证明可学习**：即使区域存在，学一个排序器仍有 v4/mamba 线那种"信息在但学不到"的风险；Phase 3 必须与 Bound-only、Rule-region、GBDT 严格对照。
3. **不能证明新颖性**：最优交叉（Aggarwal 1997）、CHILS 2025 的 Difference-Core、GLNS 2026 的不稳定性引导都是直接先例。本普查只回答"这条路上还有没有可拿的量"。
4. **不能外推到分布外**：只在 RB200–300 冻结验证集上；换分布、换规模都要重做。
