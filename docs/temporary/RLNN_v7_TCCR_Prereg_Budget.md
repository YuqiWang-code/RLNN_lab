# RLNN v7 · TCCR 预算门：预注册（跑之前写定）

> 本文件在跑 0.5 秒 / 1.0 秒预算对照**之前**写定。看到结果后不改门槛、不改保留时间、不换种子。
> 结果写进 [RLNN_v7_TCCR_Results.md](RLNN_v7_TCCR_Results.md) 的预算一节。

## 1. 要回答的问题

固定工作量下，K=20 轨迹重组在冻结 PAVE 之上还有 **+0.088**（三种子，69 胜 231 平 0 负），但那是"免费"口径：搜索已经跑完 100 步，重组只是多花 CPU。真实部署是**同一个截止时间**，重组的时间必须从搜索里扣。

所以预算门只问一件事：**把重组塞进 0.5 s / 1.0 s 的窗口，整体解变大还是变小。**

## 2. 两个臂

| 臂 | 搜索截止 | 后处理 |
| --- | --- | --- |
| `baseline` | `deadline − 0.05` | 冻结 PAVE（`deadline` 内自适应） |
| `recombine` | `deadline − 0.05 − 0.02` | 精确重组（≤0.02 s，超时保留原解）→ 冻结 PAVE（`deadline` 内） |

- 两臂**总预算相同**；`recombine` 臂把 20 ms 从搜索里扣给重组。
- 重组算子用 `models/mis_v7_fast.py`：一次批匹配算出全部 190 对的精确 `ν`，只有可能改善的对才调用精确算子；结果与穷举完全相同（`check_v7.py` 断言）。
- 重组后仍跑**同一个冻结 PAVE**，参数与步数上限不动。
- 搜索段的解码沿用冻结协议：每 10 步解码一次（这里解码全部 K 个粒子并取 argmax，GPU 工作量与只取 argmax 相同）。
- 计时口径：`solve_time_s` 从进入该图开始到 PAVE 结束，含拓扑、搜索、解码、重组、PAVE 与可行性检查。

## 3. 门槛（写死）

| 门 | 条件 |
| --- | --- |
| **B1** | 0.5 s：图级配对 Δ（`recombine − baseline`）95% CI 下界 **> 0** |
| **B2** | 1.0 s：同上 CI 下界 **> 0** |
| **B3** | 两档的平均 Δ 都 **≥ +0.05**（固定工作量边际 +0.088 的一半，作为"值得增加复杂度"的下限） |
| **B4** | `recombine` 臂的负例占比 **≤ 10%**（单调算子的优势必须体现在这里） |
| **B5** | 两臂的 `deadline_overrun` 都为 0，且实测重组段 ≤ 25 ms（保留 20 ms ＋ 5 ms 容差） |

判决：

- B1∧B2∧B4∧B5 且 B3 → `budget_pass`：重组可作为"确定性前置步骤"进论文，补 1,000 图与 K 扫描。
- 只过一档 → `budget_partial`：报告哪一档成立，不宣称两档都行。
- 否则 → `budget_fail`：固定工作量的 +0.088 不可部署，v7 线结束。

## 4. 这次跑不出什么

1. 不证明跨分布（BA/ER）成立；不覆盖作者 1,000 图。
2. 不排除 GPU 争用的影响：两臂同进程、同图、同种子相邻执行，配对比较；但绝对均值不可与历史 19.677 之类的记录横向比较。
3. 不回答"K=40 会不会更好"。
4. 重组保留了 20 ms 的固定切片；更省时的实现（例如只重组 top-12 粒子）会得到不同折中，本轮不测。
