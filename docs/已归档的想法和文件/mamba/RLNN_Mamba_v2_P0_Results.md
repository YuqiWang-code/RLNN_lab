# RLNN 静态先验 v2 · P0 接口普查结果

**判决：`oracle_direction`。** oracle 剂量 0.5、来源 KaMIS。接口有明确杠杆：T100 上 +0.40 到 +0.45 个节点，T800 天花板 +0.14，0.5 秒 +0.19；反向 oracle 全程为负且随剂量单调。所有学习方向（`amp@A` 与 `rand@A`、v1 完整偏置、v1 仅节点项）在任何剂量下都不超过空对照带。

[设计与方案](RLNN_Static_Prior_v1_Postmortem_and_v2_Plan.md) · [运行入口](../../train_scripts/mamba/v2/README.md)

## 设置

验证集前 100 图、每图 3 个搜索种子、K20；主口径 FP32 ＋ CUDA Graph；`amp@0` 与 B 逐位一致、每档 `amp@A` 与 `rand@A` 的节点偏置 RMS 相同（预检断言通过）。表内为 A.3 加冻结 PAVE-Stats H1 后的 Mean Size，配对差为图级重采样 95% CI。空对照带取换种子与固定随机臂各自有符号效应的 CI 绝对端点最大值。

曲线一次求解到 800 步、在第 25/50/100/200/400/800 步解码；预算档独立进程、含策略准备并给 PAVE 预留 0.05 秒，每档 1 次重复（换种子的空对照已覆盖采样噪声）。本轮 0.5 秒平均只跑 673 步，与同卡其他项目共享 GPU，绝对值不与 v1/v5 记录直接比较；组内配对可比。

## 四条结论

1. **接口不是瓶颈，方向才是。** 同一个接口在方向正确时值 +0.45（T100），在方向反转时值 −0.29，在方向随机时值 −0.09。v1 的五维/八维学习方向在峰值 0.007–0.71、即 0.02 到 2 的六档上全部落在 ±0.04 内，且与其同 RMS 随机对照无差别（`amp@2` 对 `rand@2` 为 +0.053，区间 [−0.017, +0.120] 跨零）。
2. **"振幅不够"的假说被否掉。** 若振幅是瓶颈，`amp@A` 应随 A 单调上升；实测六档无趋势，而"任意方向的大振幅"反而有害（`rand@2` 在 T100/0.5/1.0 秒/T800 上分别为 −0.093/−0.067/−0.083/−0.060，区间均不含零）。**搜索对节点偏置敏感，只对正确方向敏感。**
3. **静态先验的价值是"更快"加上"更高一点"。** oracle 在 T25 就达到 B 在 T800 才达到的 19.96，把 T100→T800 的 0.31 缺口整段补齐；同时把饱和值从 19.927 抬到 20.070（+0.14 [+0.09, +0.20]，空对照带 0.07）。B 自身在 0.5 秒已接近饱和，所以部署档收益只有 +0.19，1.0 秒降到 +0.09。
4. **v1 的节点项确实近乎为零。** `centered` 与 `v1-node-only` 的节点偏置 RMS 都是 **0.0026**，比最小的 oracle 档（0.283）低两个数量级，比 `amp@0.02`（0.007）还低。这一个数字就解释了 v1 的 250 个配对全同。

## 机制与口径

- **步数不是混淆项。** 0.5 秒档里 oracle@1 完成 823 步、B 完成 673 步、anti-oracle@1 只有 474 步；但逐图 `corr(Δsteps, Δsize) = −0.06`，大小收益不能由步数解释。步数差异本身是政策的因果后果：越接近独立集，A.3 的 while 循环越早收敛，解码越便宜，同样 0.5 秒能多采样。这一条同时说明墙钟口径会奖励"状态更干净"的策略，需要在论文表述里写明。
- **空对照带按"效应统计量"定义。** 换种子对的 CI 与固定随机臂的 CI 取绝对端点最大值；逐图幅度（`null_swaps 0.38`、`random_direction 0.19`）单列。本轮该定义使 T100 门槛落在 0.17，oracle 的 0.40–0.45 远超，`amp@` 的 ±0.04 远不及。
- **本轮未做**：作者 1,000 图、三种子；`--repeats 2` 反序重复（P0 只判大小，计时顺序由 P1 的 `speed` 门控制）；`diagnose_static_leverage` 的轨迹分歧汇总。

### P1 判读预注册

在结果落地前先写死读法，避免事后解释。

| 检查 | 门槛 | 依据 |
| --- | --- | --- |
| 效应 | `centered` 在 T100、T400、0.5 秒、1.0 秒四个协议上同时 `ci95[0] > null_band`，且两次重复同号 | `oracle_direction` 已证明接口可达；P1 问的是"能否学出方向" |
| 机制 | `masked` 与 `matched-rand` 的 ΔSize 都落在空对照带内 | 否则效应来自常量项或任意方向 |
| 分辨率 | `se ≤ 0.02` | 100 图 × 3 种子 |
| 速度 | 两档预算 `step_loss ≤ 2%` 且 `p95 ≤ 预算 + 5 ms` | 一次性准备成本 |
| 剂量 | 训练后 `node_bias_rms ≥ 0.28`（本页 `oracle@0.5` 的值） | 低于此值说明训练幅值没到通过档 |

### 方向学习的三段诊断

训练一结束先看这三个数，再决定后续，而不是只看 pass/fail。

1. `train_oracle_mse` 的收敛值：到 ±1 标签的回归误差。若停在 0.2 以上，说明 8 维 MLP 表达不出 oracle 那种"尖锐"的方向。
2. `node_bias_rms`：实际注入的节点 RMS。目标 0.28–0.57。
3. **方向一致性**（新增 `models/probe_direction_agreement.py`）：把训练后的 `direction` 与 oracle 的 ±1 标签比 cosine、秩相关与 top-k 重合，并扫 `λ ∈ {0, .25, .5, .75, 1}` 的插值偏置，画出"学到的方向覆盖了 oracle 效应的百分之几"。`λ=0` 复现 `amp@0.5`，`λ=1` 复现 `oracle-kamis@0.5`（两者都有断言，可交叉核对本页数值）。

```bash
# 先冒烟：2 图 × 1 种子 × λ∈{0,1}，约 30 秒，验证两个端点断言
CUDA_VISIBLE_DEVICES=0 python models/probe_direction_agreement.py --ref 0 \
  --checkpoint outputs/mamba_v2/oracle_centered8_ref0 --samples 2 --steps 25 \
  --seeds-per-graph 1 --lambdas 0 1 --output outputs/mamba_v2/probe_smoke
# 正式：100 图 × 3 种子 × 5 个 λ
CUDA_VISIBLE_DEVICES=0 python models/probe_direction_agreement.py --ref 0 \
  --checkpoint outputs/mamba_v2/oracle_centered8_ref0 --steps 100 --seeds-per-graph 3 \
  --oracle-kamis-path outputs/mamba_v2/oracles_ref0_fp32-graph/oracle-kamis.json \
  --output outputs/mamba_v2/probe_direction_ref0
```

分档判读：

| cosine | λ 曲线在 0.5 处的位置 | 含义 | 动作 |
| --- | --- | --- | --- |
| ≳ 0.5 | 已拿到 oracle 效应的 ≥ 50% | 方向学得动，只是弱 | 提 node_limit、加训练轮次，或换软标签 |
| 0.2–0.5 | 10%–50% | 目标函数不够对齐 | 换成入选频率软标签（`probe_v7_context.elite_frequency`）或加权 MSE |
| ≲ 0.2 | ~0 | 回归到 ±1 学不出方向 | 换标签来源或换目标（对比/rollout 收益），不再调幅度 |
